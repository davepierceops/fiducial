## F-1 — blocking
Claim: The worked exclusive-assignment example names two different directories — it declares the tree at `"wt/<name>"` and then creates `"wt/<n>"`.
Location: skills/directive-invariants.md:89–95 (`## Working-tree disposition prompt`, second fence), both tokens on :91
Evidence: Verified by reading the diff and by running. The baseline at 7c233c15 read `worktree at "wt/<name>", created by: git worktree add "wt/<name>" main` — one token, used twice. The revision's O-1 edit rewrote only the command, to `git worktree add --no-track "wt/<n>" -b <branch> origin/main`, leaving the declaration's `"wt/<name>"` untouched; the decision record's own restatement of the resolution carries `"wt/<n>"`, so the substitution came in with the dictated wording. Run against the shipped code, the statement still passes M3: `elements.m3` over the example as an unfenced statement returns `('pass', None, None)`, and `elements._QUOTED_TOKEN` finds both tokens — `[('wt/<name>', ''), ('wt/<n>', '')]` — so the form test is satisfied by either and the disagreement is invisible to the lint.
Consequence: This fence is emitted verbatim into every generated skeleton in both modes, immediately below the governed rule it works, and it is the only worked exclusive assignment an author ever sees. The rule it is working requires "a named directory plus the command creating it"; the example names one directory and creates another, so it does not instantiate the rule it sits beneath. An author copying it writes a disposition whose declared tree and created tree differ, and no check anywhere catches that: the lint passes it, and a reader with only the bundle has nothing to decide which token was meant. `<n>` and `<branch>` are also undefined in the example, where the baseline's single `<name>` was self-explaining.
Fix: Make both tokens the same placeholder, `"wt/<name>"` in the declaration and in the `git worktree add` argument, keeping the rest of the O-1 command as landed. Criterion 1.

## F-2 — non-blocking
Claim: The preamble's rule that the disposition label appears in this document only inside fenced blocks is false of this document under the TRD's own definition of the label.
Location: skills/directive-invariants.md:40, against :205
Evidence: Verified by running. `mdmask.eligible` over the file returns line 205 as eligible — it is prose, in no fence — and line 205 contains `WORKING-TREE DISPOSITION` inside an inline code span, which §3.5 masks nothing about. Consequence: TRD §3.2 states the fence-only property as condition 2 of the three that make G3 hold, and states it as "That document contains the label only inside fenced blocks … asserted by one test that reads it and applies §3.5's mask". ## F-3 — non-blocking
Claim: `## Disposition label` states the exclusive-assignment form's membership test but not the sole-tree form's, so form-membership cannot be decided from this file.
Location: skills/directive-invariants.md:226–239
Evidence: Verified by reading and by running. Line 227–228 says exactly one of the two forms must be present over the extent; lines 230–231 give the exclusive-assignment test explicitly; lines 235–239 give the canonical sole-tree sentence under the bare heading "Canonical sole-tree sentence:" with no statement of how it is tested. ## F-4 — non-blocking
Claim: The new eligibility prose says line endings are normalised without saying which endings, or to what.
Location: skills/directive-invariants.md:216–217
Evidence: Verified by reading, against the shipped rule. The document reads "Line endings are normalised before masking, and the match is byte-exact thereafter." TRD §3.5 states the rule completely — "`\r\n` and `\r` are normalized to `\n` before masking" — and `mdmask.normalize_endings` implements exactly that. Every other clause in the same two paragraphs was carried at full strength and each was confirmed against the shipped masker: the fence rule at three-space and four-space indents, the short-close and unclosed-fence cases, blockquotes bare and indented, HTML comments spanning lines and on one line, indented code left eligible, and all four stripping steps applied once each in order.

## F-5 — non-blocking
Claim: The preamble fixes the placeholder syntax without stating its escape, so region text cannot show a placeholder.
Location: skills/directive-invariants.md:24, :38
Evidence: Verified by reading the shipped substituter. `invariants.substitute` opens with "Replace `{{name}}` from a closed set; `{{{{` is a literal brace pair" and implements it: a doubled `{{{{` emits one `{{` and advances past both. Consequence: The document is the one place a region's text is edited, and every region body is a template. Fix: Add the escape to line 24's sentence: `{{{{` is a literal `{{`. Criterion 1.
