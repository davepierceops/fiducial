## F-1 — non-blocking
Claim: E2 imports the invariants document's term of art "eligible" into this file, which neither defines it nor marks it as defined elsewhere, so an agent reading this file inside a bundle applies a bound stricter than the one the design and the check hold.
Location: `skills/directive-authoring.md:22-23`, against `skills/directive-invariants.md:25-29` and `:223-231`
Evidence: *Observed*, verified by reading and by running. The bullet reads "**The disposition label leads the disposition statement and no other eligible line.**" The word "eligible" occurs exactly once in this file — `grep -n eligible skills/directive-authoring.md` returns `:23` and nothing else — and this file states no eligibility rule, names no holder for one, and gives the word no gloss. Eligibility is a defined term: `skills/directive-invariants.md:223-231` states it (fenced blocks, blockquote lines, and HTML comments mask; indented code blocks do not), and `bin/aimeta/mdmask.py:36-71` implements exactly that. The invariants document, which *contains* that definition, still glosses the term every time it binds an editor with it: `:25`–`:26` reads "No eligible line of this document — eligibility as the Disposition label section defines it — leads...". This file binds an author with the same term and attaches no such gloss. The preceding bullet is not the gloss: it names the Directive Invariants document as the one definition of three enumerated things — the label's fixed form, the canonical sole-tree sentence, and a worked example of each form (`:18`–`:20`) — and eligibility is not among the three, so a reader following that pointer is following it to a list that does not include the term they are stuck on.
Consequence: An agent that has never seen the repository reads "no other eligible line" as ordinary English — a line that is *allowed* to carry the label — and has no signal that a technical definition is in play. Read that way the bullet is a strictly wider prohibition than the design holds, and it re-creates the exact authoring failure cycle 4's F-2 removed by a different route: an author writing a gate or amendment directive that quotes its predecessor's disposition inside a blockquote reads this bullet as forbidding it, and avoids a shape `bin/aimeta/mdmask.py` masks and `specs/directive-tooling-trd.md` §3.5 names as the common case. The failure is silent both ways — M3 stays green on the shape the author avoided, and nothing in this file tells the author they were reading a term of art. Criterion 1: the file is written to be read inside a generated bundle by an agent that has never seen the repository, and here the file is readable and wrong rather than unreadable, which is the harder failure to catch. Criterion 3's middle sentence — "If the file needs something another file states, it states it" — reads on it too, but is not cited alone: cycle 4's O-2 settled that criterion 3's operative test is its third sentence and that a bare co-bundled dependency is admitted, and this finding does not reopen that reading. What it names is narrower than the dependency: the absence of any marker that a dependency exists.
Fix: Either gloss the term where the invariants document glosses it — "and no other eligible line, eligibility as the Directive Invariants document defines it" — which costs one clause, takes the by-title form cycle 4's O-2 admitted, and keeps the definition in the one file that holds it; or widen the previous bullet's enumeration to name eligibility as a fourth thing that document defines. The first is smaller and puts the marker on the sentence that needs it. Not a wording change to the bound itself: "eligible" is the correct term and cross-check 3 above confirms it now agrees with the invariants document, the TRD and the shipped mask.
