## F1 — non-blocking
Claim: AC-LAND-01b's new given restricts the criterion to a working tree *behind* the branch head, leaving the tree-already-at-head case — the state the primary journey pair J1-then-J2 actually runs in — with no criterion asserting the commit's parent.
Location: specs/bin-land.md §6 AC-LAND-01b; §3 J2; §4 G1, second arm.
Evidence: Inferred by reading at this SHA. Before this revision AC-LAND-01b's given was "Given the named branch exists at the remote", covering every local-tree state. It now reads "Given the named branch exists at the remote, and a working tree behind that branch's remote head". No other criterion in §6 states a local-tree given: 01a covers the branch-absent arm, 01c covers the diverged case, and 02 through 10 state no condition on the tree at all (*observed*, read across all twelve criteria at this commit).
Consequence: A Test Designer deriving cases from §6 now sets AC-LAND-01b up from a tree behind the branch head and has no criterion directing them at the ordinary J2 state, where the same session's prior invocation put the tree at or under that head. The core parentage assertion — that the commit's parent is the branch's remote head as of this invocation's own fetch — would be tested only in the rarer state and not in the one every session runs. This is cycle 3's F1 with the two states exchanged: the criterion covers one state and G1's arm governs both.
Fix: Widen the given rather than replacing it — "Given the named branch exists at the remote, and a working tree at or behind that branch's remote head". Two words, and it keeps the state cycle 3's F1 induced while restoring the one it displaced. AC-LAND-01c continues to carry the third state, so the three criteria then partition the local-tree states exhaustively.
Related: O1.

## F2 — non-blocking
Claim: §1 describes `bin/land` as a tool that "lands what the executor already committed", which is the precise starting state G1's second arm now refuses.
Location: specs/bin-land.md §1, `DEC-000160` bullet (line 50); §4 G1, second arm; §4 G2, G3.
Evidence: Inferred by reading at this SHA. §1 reads: "it is an execution-session tool that lands what the executor already committed and reads the result back". G2 and G3 say the tool stages the named files and makes the commit, so the executor has not committed when the tool runs — a looseness that stood harmlessly through three cycles because nothing keyed on it. G1's new clause keys on it: a local tree carrying a commit the fetched head lacks is exactly a tree where the executor already committed, and the tool now refuses that tree, names the divergence, and exits non-zero.
Consequence: The two sections now describe incompatible tools. A reader who takes §1 literally — an implementer at the TRD stage, or a Test Designer sourcing the primary use case — builds or tests a tool whose normal input is a local commit, and every such invocation refuses under G1. An executor who reads §1 as instruction commits first and gets a refusal on the primary path. §4 is the normative section and wins on any careful reading, which is why this is not blocking, but the sentence is now wrong rather than merely loose.
Fix: Reword §1's clause to match G2/G3 — "an execution-session tool that lands the work the executor produced in its own tree and reads the result back". The bullet's point is the contrast with a decision-session tool gating a chat-side write, and that point survives the rewording intact.
Related: F1.

## O1 — observation

Location: specs/bin-land.md §4 G1, second arm; §4 G2.
Evidence: Inferred by reading, comparing against cycle 3's O2 `Evidence` field, which recorded two gaps: the diverged case, and "the mechanism by which the base is established when the tree is elsewhere ... whether the tool moves the tree, refuses, or requires the caller to have arrived there". A TRD can pick any of them without violating a stated goal. Nothing in §6 is untestable as a result; AC-LAND-01b as widened per F1 asserts the parent, which is the observable part.
