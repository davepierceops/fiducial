## F-1 — blocking
Claim: M2's decided mechanism does not decide the property M2 states — `git log -1 --format=%H <sha> -- <path>` returns non-empty whenever *any* ancestor of `<sha>` touches the path, not when `<sha>` itself does.
Location: `specs/directive-tooling-trd.md:471-476` (§3.6, M2).
Evidence: **Verified by running**, in this clone. `git log -1 --format=%H ed46f40 -- specs/directive-tooling.md` returns `9e61252b9ff425392a4a99a52f40456033ad924c` — a different commit — while `git show --stat --format=%H ed46f40 -- specs/directive-tooling.md` shows `ed46f40` touches no file at that path. The command is non-empty for a commit that does not touch the path.
Consequence: AC-DT-09's third fixture — "commit touching a different path (fail)" — passes instead of failing under this mechanism, in any fixture repository where the cited path was added before the cited commit, which is the natural construction. The Test Designer either writes AC-DT-09's fixture to the criterion and gets a red the implementation cannot clear, or writes it to the mechanism and silently retires the criterion. PRD M2's own words — "a SHA that resolves to a commit **touching that path**" — are not satisfied, so the lint would accept nearly every SHA in the repository for any long-lived path.
Fix: Decide M2's touch test against the commit itself — `git diff-tree --no-commit-id --name-only -r <sha> -- <path>` non-empty, or `git log -1 --format=%H <sha> -- <path>` compared for equality with the resolved `<sha>` — and state which, so AC-DT-09's four fixtures are derivable from the text.

## F-2 — blocking
Claim: The invariants document is read from the **methodology home** while its committed content is resolved with **root-scoped** git calls, and the two are not the same tree — nor is the home a git repository at all in the test substrate this document chooses.
Location: `specs/directive-tooling-trd.md:181-188` (§3.2, "Resolution is against committed content") against `:502-506` (§3.7, the methodology home) and `:634-666` (§4.1) and `:660-661` (`invariants_doc(home, ...)`).
Evidence: **Verified by running and by reading.** `bin/aimeta/repo.py:76-92`: `methodology_home(root)` returns `$AI_METHODOLOGY_HOME`, else `root`, else `root.parent/"ai"` — three candidates, two of which are not `root`. `bin/aimeta/repo.py:94-101` and `:130-141`: `last_commit_sha(root, relpath)` and `file_at_rev(root, rev, relpath)` both run git with `cwd=root`. `bin/tests/helpers.py:251-267`: `make_home` creates a plain directory — a policy copy, role documents, a `bin/` symlink — and never runs `git init`; `grep -rn "make_home" bin/tests/*.py` shows every consumer pairs it with a separately-rooted `make_repo` (`bin/tests/helpers.py:134-148`), and no test git-initialises a home.
Consequence: In the substrate §4.1 adopts, `last_commit_sha(repo, "skills/directive-invariants.md")` returns `None` — the file is not in that repo — so under §3.2 the generator has no committed body to copy and under FM-G3 no `git status` to read. Every generator test fails at the first invocation, and AC-DT-01 ("changing the committed text of a source changes the next skeleton") is not merely red but uninstantiable: there is no commit to change. The same holds in production for any consumer repository using a sibling or `$AI_METHODOLOGY_HOME` checkout, which is the configuration the home mechanism exists for. §3.9's "most likely red" names only the *absence* of the document from `make_home`, not the absence of a repository around it, so a Test Designer following that paragraph fixes the wrong thing.
Fix: State which tree the invariants document's revision is resolved in — the methodology home, with `last_commit_sha`/`file_at_rev` given the home as their root — and state what §4.1's substrate must therefore do (`git init` and commit inside `make_home`), or state the fallback when the home is not a repository and what AC-DT-01 asserts in that case.

## F-3 — blocking

## F-5 — blocking
Claim: §3.9 fixes two different destinations for the general-mode skeleton — the path `--write` names, and a generator-computed `docs/cycles/<descriptor>-<YYYYMMDDThhmmss>Z.md` — and the document never reconciles them.
Location: `specs/directive-tooling-trd.md:561-566` ("General mode's skeleton destination is therefore **`--write`**… without it the skeleton and manifest go to stdout") against `:573-577` ("General mode writes to `docs/cycles/<descriptor>-<YYYYMMDDThhmmss>Z.md`"); restated as the `--write` path at `:748-749` (§5) and as "the named output path" in AC-DT-12(c); FM-G5 at `:789` and OQ-4 at `:1078-1084` both speak of "an existing `--write` destination".
Evidence: **Verified by reading**, both statements in the same subsection, three paragraphs apart, with no clause subordinating either.
Consequence: The two readings give different tests. If `--write` names an arbitrary path, PRD §7's stated mitigation for the M8 mode-appropriateness risk — "the generator makes the name correct by construction" — is false, and the generator can be made to emit a skeleton its own lint fails M8 on, which is the state PRD §4's Conflict rule reserves for surfacing. If the name is computed, `--write` is a boolean and §5's "the path `--write` names" and AC-DT-12(c)'s "named output path" are wrong. The Test Designer must pick one to write AC-DT-12(c)'s tree-diff test and any assertion about where the skeleton lands, and either pick silently retires part of the text.
Fix: State the flag's arity once — either `--write` takes the destination and the timestamped name is what the generator suggests, or `--write` is a switch that writes to the computed `docs/cycles/` path — and make §5, FM-G5, OQ-4 and the AC-DT-12(c) framing agree with it.

## F-7 — blocking
Claim: The exclusive-assignment form is decided as a `git worktree add` invocation plus a **quoted or backticked** path token — narrower than the governed rule in both halves, and the narrowing is not recorded as a question.
Location: `specs/directive-tooling-trd.md:382-385` (§3.4, form-membership).
Evidence: **Verified by running and by reading.** The governed rule at `skills/directive-authoring.md:13-15` admits "an exclusive assignment (a named directory plus the command creating it)" — it names neither `git worktree add` nor any quoting. PRD M3 carries the same wording verbatim. Over `docs/cycles/`, `grep -rhoE "^[-*> ]*\**WORKING[- ]TREE[^:]*:"` returns 33 label lines, of which 29 take the form `WORKING TREE — exclusive assignment… From the clone root:` and introduce their command in a following block rather than a quoted token on the extent's own lines. The document flags the parallel narrowing on the *other* branch — OQ-7, for the sole-tree literal — but not this one.
Consequence: AC-DT-13 states "Every element M1–M8 satisfies this as written" — that no requirement is enforced which no governed file states. A quoting requirement is such a requirement, and so is the restriction of "the command creating it" to one subcommand. The Test Designer writing AC-DT-13 encodes both as agreed, and writes AC-DT-06's fixtures (i) and (iii) to a shape the governed rule does not require, which then becomes the shape authors must write. This is not the accepted false-stop risk of PRD §7: that risk is a mis-parse, not a rule the lint adds.
Fix: Either derive the exclusive-assignment test from the governed wording (a path-shaped token and *some* tree-creating command, both unquoted-tolerant), or record the narrowing as an open question alongside OQ-7 so it is ruled rather than assumed.

## F-9 — blocking
Claim: `--date` cannot make the general-mode filename deterministic — it fixes a date, and the filename carries a time.
Location: `specs/directive-tooling-trd.md:573-577` ("with `--date` fixing it for determinism as AC-CO-10 already does for cycle mode's `Date:` line").
Evidence: **Verified by running.** `docs/packages/package-a-spec.md:414-415` (AC-CO-10): "`--date` fixes the `Date:` line (determinism for tests); otherwise today's local date in `YYYY-MM-DD`". `bin/cycle-open:49` declares `--date` with `metavar="YYYY-MM-DD"`, and `bin/cycle-open:174` uses it as `args.date or datetime.date.today().isoformat()` — a date, with no time component, and local rather than UTC. The general-mode name the TRD fixes is `<descriptor>-<YYYYMMDDThhmmss>Z.md`, UTC.
Consequence: There is no stated way to fix `hhmmss`, so the Test Designer cannot write a deterministic expected path for the general-mode skeleton — needed for AC-DT-12(c)'s tree diff, for FM-G5's existing-destination refusal, and for any AC-DT-05 or AC-DT-18 assertion that names the emitted file. Whatever they choose (a regex, a frozen clock, a synthesised `000000`) becomes an unstated part of the contract, and the local/UTC mismatch between `--date`'s existing meaning and the filename's zone is inherited into it.
Fix: State how the general-mode timestamp is fixed for tests — a distinct flag, an extended `--date` accepting a full `YYYYMMDDThhmmss`, or an injected clock — and say what it does to AC-CO-10's existing `--date` contract, which cycle mode must keep.
