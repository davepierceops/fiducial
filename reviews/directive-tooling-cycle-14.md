## B1 — blocking
Claim: M3's whole-file branch admits a **false negative** — a directive stating no working-tree disposition exits **0** on M3 whenever any text elsewhere in the file instantiates exactly one admitted form — and no goal, criterion, NFR, or accepted-risk item names this. §7 states the branch's residual is false-positive-only, and its one accepted false-negative item is scoped to elements the lint *cannot* check, not to a checked element returning the wrong answer.
Location: specs/directive-tooling.md §4 M3 row (`specs/directive-tooling.md:696`); §4, "Why the other branch is the whole file, and on what ground" (`:745-762`); §4, "What this branch costs, and where the cost is already accepted" (`:763-773`); §7, "Its direction is the **false positive**, not the false negative" (`:2067`); §7, "The primary risk is the halo, not a false negative" (`:1993-2000`); §6 AC-DT-06's M3 fixture set.
Evidence: **Inferred by reading**, at the reviewed commit; no tool exists to run (see *Not inspected*). M3's element text is a presence test for "**exactly one** of two forms: an exclusive assignment (a named directory plus the command creating it), or a literal sole-tree declaration" (*observed*, `:696`). In the whole-file branch the extent is "the whole file" (*observed*, `:696`, `:745-752`), so every line of the directive is in range, not only its working-tree section. The document's reasoning about that branch runs in one direction only: `:763-773` reasons about a file carrying generator-sourced text naming **both** forms and concludes the exit is non-zero, and §7 at `:2067` states the residual's "direction is the **false positive**, not the false negative". `grep -c "false negative"` over the document returns **2** (*observed*), and both are the sites above: `:2067` denies the direction for this residual, and `:1993` frames the false negative as not the primary risk and accepts "a directive that passes the lint and is still wrong" for "the elements it **cannot** check — self-containment, non-contradiction, correctness of the dictated content, executability of the disposition" (*observed*, `:1993-2000`). M3 is a checked element, so that acceptance does not reach it. No fixture in AC-DT-06's M3 set is of the shape below: the neither-form fixture, the both-forms fixture, the two single-form fixtures, and the prohibition fixture each have their form-instances (or absence) in the working-tree statement itself (*observed*, by reading the criterion), so none discriminates a form-instance sited **outside** the disposition.
Consequence: Take a hand-written directive — no manifest, so the whole-file branch — whose working-tree section states only a **prohibition** ("Do not create a worktree; do not touch the main clone"), and whose stop conditions or provenance note elsewhere contain a named directory plus the command creating it, for example "STOP if you cannot create the assigned tree with `git worktree add "$TMPDIR/foo"`" or "the prior cycle ran `git worktree add "$TMPDIR/bar"`". M3 searches the whole file, counts **exactly one** admitted form, and exits **0** on that element. The directive states no disposition of its own, and the lint says so is fine. That is the motivating incident — "the directive in that incident stated a prohibition and no disposition of either admitted form" (*observed*, §3 J3) — reaching exit 0 on the very element the document introduces to catch it, and J3's claim that M3 "fails" on the incident holds only because the incident's file happened to carry no such text elsewhere. The branch trades a **named** false-positive residual for an **unnamed** false-negative one, and the trade is not stated anywhere: §7's accepted list would have Dave sign a residual set that does not include this. Two further points bound the finding honestly. First, it is **not this cycle's regression**: the whole-file extent is the cycle-12 directive's B1 disposition, the cycle-12 self-gate did not raise it, and the cycle-13 independent gate — which found the branch's *ground* falsified — did not raise it either; this revision inherits it with the ground repaired and the direction claim unchanged. Second, the **locating branch is unaffected**: there the extent is the author region, so text sited elsewhere is out of range by construction, which is why the defect is specific to the branch that reads the whole file.
Fix: This needs a disposition, not a wording change, and the choice is Dave's; none is taken here. Three are available and each is **clearly labelled as a proposal**. **(a) Name it and accept it.** Add the false-negative residual to §7 beside the false-positive one, state its shape, and correct `:2067` so the direction claim is scoped to the residual it is actually about. Cheapest, and it makes the acceptance auditable, but it leaves the motivating incident's mechanical catch defeasible by ordinary directive text. **(b) Narrow M3's whole-file extent.** Have the whole-file branch search only the file's working-tree statement as a structural region rather than the whole file — which requires a structural anchor a manifest-less directive does not carry, and so probably collapses into (c). **(c) Require the disposition to be locatable.** Make an unlocatable disposition an undecidable element under AC-DT-10 rather than a whole-file search — the option the cycle-11 gate's B1 named and this document declined, at the cost of putting every hand-written directive outside M3's range. Whichever is taken, AC-DT-06 should gain a fixture of the shape in *Consequence* — a manifest-less directive whose only working-tree statement is a prohibition and which carries a form-instantiating line elsewhere — so the choice is pinned by a test rather than by prose, which is what cycle 8's B2 fix did for pattern 3 and what cycle 11's did for the scoping pair.

## N1 — non-blocking

The revision fixes it in M3's row and adds a precedence rule, but **two sites restate the test in full** rather than referencing it, so the single-source property is achieved by precedence rather than by construction and the drift the disposition targets is mitigated, not removed.
Location: specs/directive-tooling.md §4 M3 row (`specs/directive-tooling.md:696`, where the predicate and the precedence rule are stated); §4, "Being handed the whole file is not the same as every element ranging over the whole file" (`:956-963`); §6 AC-DT-06's M3 clause (`:1634-1641`).

But the *test* appears in full at two further sites, in declarative form: `:962` reads "whether a conforming G11 manifest carried by the file locates the disposition author region — and is that region's extent where it does and the whole file where it does not" (*observed*), and AC-DT-06 reads "the disposition author region where a conforming G11 manifest carried by the fixture locates it, and the whole file in every other case" (*observed*). Both agree with M3's row today; I checked each clause against the row and found no divergence. M3's row carries the mitigation: "Every other mention of M3's extent in this document is a **reference to this row** and states no test of its own; where any of them appears to say something different, this row governs" (*observed*, `:696`).
Consequence: There is no ambiguity **at this revision** — the three statements agree, so no two implementers diverge, which is why this is not blocking. AC-DT-06's M3 clause needs the branches only to say which extent a fixture is judged in, which a cross-reference plus "the branch that fixture falls in" carries. Alternatively, keep the restatements and state explicitly that they are recaps subject to the row's precedence — which is close to what the row already says, and would make the row's claim exactly true.

## N3 — non-blocking
Claim: The third shape M3's predicate enumerates — "a conforming manifest that locates no disposition author region" — may be **vacuous**, because G11 appears to make naming that region part of conformance; if it is, the predicate is extensionally the conforming-manifest-present binary and the document implies a distinction it does not draw.
Location: specs/directive-tooling.md §4 M3 row (`specs/directive-tooling.md:696`); §4 G11 (`:604-643`, esp. the "exactly two author-marked regions" clause); §4, "Why the other branch is the whole file" (`:753-762`, "The three shapes that fall in this branch are **one case, not three**").
Evidence: **Verified by reading**, at the reviewed commit. G11 requires that "the manifest names every region in emission order", that each entry carry "either the committed path that region was read from or an explicit marking that the region is an **author** region", and that "the manifest therefore admits **exactly two** author-marked regions, the task-specific region and the disposition author region, which AC-DT-18 distinguishes by name" (*observed*, `:604-628`). Read strictly, a manifest that does not name the disposition author region does not satisfy G11, so "conforming **and** non-locating" is empty and the predicate's second and third shapes collapse into one. The document does not say whether it is empty; it says only that "nothing in the branch turns on which of the three it is" (*observed*, `:756-758`).
Consequence: No behavioural ambiguity — the predicate is a single test either way and every input still has an extent, which is why this is not blocking, and the enumeration being belt-and-braces is defensible on its own terms. What it costs is precision about what changed at this cycle. The cycle-13 gate's B1 was an equivocation between manifest **presence** and manifest **locatability**; if conformance entails location, then the revised predicate keys on "a conforming manifest is present", and the substantive change from the previous revision is the word **conforming**, not the move from presence to locatability. That is a materially different account of the fix from the one §4 gives, and the third gate should be told which it is rather than deriving it. There is also a live TRD-stage consequence: if the shape is not vacuous, the TRD must say what a conforming manifest missing that entry looks like, and G11 currently forbids it.
Fix: One clause in M3's row or in G11 stating whether a G11-conforming manifest necessarily locates the disposition author region. If it does, say the third shape is enumerated for robustness against a TRD-stage definition of conformance that does not entail it, and that it is empty under G11 as stated. If it does not, G11 should say which of its clauses a manifest may fail while still conforming.
Related: N1.
