## F1 — non-blocking
Claim: The behaviour newly stated in G1's second arm has no criterion in §6 that induces its starting state, so §6 no longer covers all of §4's normative content.
Location: specs/bin-land.md §4 G1, second arm; §6 AC-LAND-01b.
Evidence: Inferred by reading, comparing §4 and §6 at this SHA. G1's second arm now asserts that a local tree behind the fetched head does not alter the outcome. AC-LAND-01b opens "Given the named branch exists at the remote" and states no condition on the local tree at all. Its sibling AC-LAND-01a does carry such a condition — "and a working tree whose checked-out branch is behind the remote default branch" — so the pattern for stating it exists in the document and is simply absent from the second arm's criterion.
Consequence: A Test Designer deriving cases from §6, which the PRD template names as the source they derive from, would set up AC-LAND-01b from a tree already at the branch head — the J1-then-J2 path, where the same invocation put it there. The one starting state the new sentence exists to rule on would go untested, and the sentence would be an unverified assertion in the goals rather than a checked behaviour. This is the same shape as cycle 1's N1: a goal whose criterion does not reach it.
Fix: Add the condition to AC-LAND-01b, mirroring AC-LAND-01a's wording — "Given the named branch exists at the remote, and a working tree behind that branch's remote head, the invocation produces a commit whose parent is that branch's remote head as of the invocation's own fetch". No new criterion is needed; the existing one gains a clause.
