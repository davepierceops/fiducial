## RR-4 — non-blocking
Claim: No criterion tests a file for contradiction with the rest of the corpus, although the artifact schema requires every artifact to declare what it cross-checked and this role's cycles are commissioned to cross-check.
Location: docs/global-context/review-rubric.md:16-55 (the eleven criteria as a set), against skills/review-artifact.md:68 (the required `Cross-checked` header line) and :24-25.
Evidence: Verified by running, in this cycle. The two strongest results this cycle produced — decision-layer.md:32 against core.md:17 and :55 (filed as DL-1), and roles/context-quality-reviewer.md:15-17 against policies/document-metadata-policy.md:32 (filed as CQR-5) — are contradictions between governed files, and neither maps onto a criterion. Criterion 4 is the only criterion that reaches across files and it tests the opposite defect: "The file does not restate a rule that Core or the Decision Layer already states" catches duplication, not disagreement, and a rule that contradicts Core passes criterion 4 precisely because it is not a restatement. Criterion 11 reaches "boundaries two roles could both claim," which is one narrow species of the class. Both findings above are therefore filed under criterion 11 or 4 as the nearest fit, which is a misdescription in the artifact.
Consequence: The artifact schema requires a `Cross-checked` line, so every artifact asserts cross-checking was done, and the rubric that defines what a review is never asks for it. A reviewer who applies the eleven criteria literally and thoroughly is not required to open a second file at all, and the corpus-wide contradictions this cycle found would pass. When one is found, the criterion number cited in the artifact names a criterion the finding does not fail.
Fix: One criterion, in the rubric's own idiom: "**The file does not contradict the corpus.** Where the file states a fact, a definition, or a rule that Core, the Decision Layer, or a governing policy also states, it states it the same way. A disagreement is a defect, and is surfaced rather than resolved." Whether the eleven become twelve is Dave's.

## RR-6 — non-blocking
Claim: Criterion 2's `order:` clause states a condition with no mechanical test, and now diverges from the field the metadata policy defines.
Location: docs/global-context/review-rubric.md:20-22 ("carries `audience:` with at least one value from the known set, and `order:` where its position in a bundle matters"), against policies/document-metadata-policy.md:114-116.
Evidence: Verified by running. `order:` entered the policy at 6211312 — `git diff 12ecaeb HEAD -- policies/document-metadata-policy.md` shows the addition — as "`order:` optional on any document. An integer fixing the document's position within a bundle, lower first. Absent means the document sorts after every ordered file." `bin/bundle:198-202` implements exactly that: `_sort_key` returns `(1, 0, relpath)` for an unordered file and `(0, order, relpath)` for an ordered one, so unordered files sort after ordered ones and then by path — position is always deterministic, and no file's position is ever undefined. Criterion 2's "where its position in a bundle matters" therefore has no state it can distinguish. At HEAD three in-scope files carry `order:` — core.md `0`, decision-layer.md `1`, prose-criteria.md `11` — and 48 do not, this file among them.
Consequence: Two governed files in the same bundle state different obligations for the same field, one unconditional ("optional on any document") and one conditional on a test neither states. A reviewer can file a criterion 2 finding against any of the 48 files without `order:`, and the author can defeat it by citing the policy; the reverse is equally available. Applied to this file it is circular: the rubric cannot say whether it needs `order:` itself.
Fix: State the condition mechanically — "carries `order:` if it must load before another file in the same bundle" — or drop the clause and let the policy's "optional" stand alone.

## RR-7 — non-blocking
Claim: Criterion 3's absolute form has no carve-out for a document whose operative content is paths, and the repository's frontmatter enforcement is configured by exactly such a document.
Location: docs/global-context/review-rubric.md:24-25 ("No references to other files by path. If the file needs something another file states, it states it. A path-shaped reference is a defect."), against policies/document-metadata-policy.md:26-37 and `bin/aimeta/scope.py:29-54`.
Evidence: Verified by reading the code. `bin/aimeta/scope.py` reads `policies/document-metadata-policy.md` at runtime, finds the line containing "In scope (frontmatter required)", and extracts every backticked value from the bullets that follow until "Out of scope" — the twelve globs at :26-37 are the enforcement configuration, not references to what another file states. The module raises `ScopeError` rather than falling back to a built-in list, documented at :1-10 as deliberate: "a silent fallback would let a policy edit stop being enforced without anyone noticing." `bin/check-frontmatter --all` confirms the coupling in its own output — "51 file(s) matched, from 12 configured glob(s)" — and the twelve are the twelve bullets. Criterion 3's first two sentences do not reach these paths; its third does, unconditionally. Two prior cycles resolved this by suppression rather than by the criterion: reviews/document-metadata-policy-cycle-16.md's Not inspected line records "the structural path references this file carries as a policy about paths, which the prior two cycles accepted as structural and which this cycle's directive excludes from report."
Consequence: The criterion is applied by directive rather than by its own text — three cycles running, a decision session had to tell the reviewer not to report it. This cycle's directive contains no such exclusion, so the same passage is a defect again, and the only honest disposition available is the one taken here: file it against the criterion instead of the file. A criterion that has to be switched off to be usable is not doing the work of a criterion.
Fix: Add the carve-out to criterion 3: "A path that is the document's operative content — a scope glob, an enumerated class, a filename the document prescribes — is not a reference and is not a defect. A path standing in for something another document states is." One sentence, and it retires a standing exclusion.
