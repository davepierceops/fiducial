## B1 — blocking
Claim: The slot split puts text naming **both** admitted disposition forms into every generated directive, outside the author's region, and no clause in the document scopes **M3's search** to a region — so a correctly-filled directive and an unfilled one are not distinguished by the same rule under two admissible implementations of M3.
Location: specs/directive-tooling.md §4, M3's row in the mechanically-checkable table; §6 AC-DT-06, the M3 clause; §4 G3, the disposition-prompt bullet; §3 J1; §6 AC-DT-03.
Evidence: Verified by reading, at the revision under review, against the source the prompt is read from. G3's prompt bullet requires the generated skeleton to carry, from `skills/directive-authoring.md` @ `48ad7fd1`, the text "either an exclusive assignment (a named directory plus the command creating it) or an explicit sole-tree declaration. A prohibition is not a disposition." — read whole at that commit and confirmed present (*observed*). M3 requires "A working-tree disposition is present, in **exactly one** of two forms." AC-DT-06 requires that "a fixture carrying both exits non-zero" and that "each of the two single-form fixtures exits 0 on that element." The lint is handed "the directive file the executor writes" and nothing else (§4, "What M8 claims"), and **no clause in M3, AC-DT-03, AC-DT-06, or G3 states where in that file M3 looks** (*observed*, by search: the strings "author region" and "scope" do not co-occur with M3 anywhere in the document).
Consequence: Concretely, take a directive generated by `bin/directive` and correctly filled with one exclusive assignment. The landed file contains (a) the prompt's naming of both forms, which the generator wrote, and (b) one instance of one form, which the author wrote. An implementer reading M3 over the whole file finds both forms named and exits **non-zero on a well-formed directive**; an implementer scoping M3 to the disposition author region exits **0**. Both readings are supported by §6 as written, so AC-DT-06's M3 fixtures do not pin the behaviour they exist to pin — structurally the same defect as cycle 9's B1, one criterion downstream, and introduced by the disposition that fixed it. The second direction is worse: an executor who leaves the author region **empty** still lands a file naming both forms, which is the motivating incident exactly — a directive with no stated disposition — and whether M3 catches it turns on the same unstated scope. Before the split this could not arise, because the file carried no form-naming text the author had not written; the split is what makes a lint that reads the whole file wrong. Note that this is a reading of the document, not an observation of a tool: neither binary exists, and no skeleton was generated (see *Not inspected*).
Fix: State M3's search scope once, at the M3 row, and make AC-DT-06 assert it. The manifest already supplies the mechanism and no new one is needed: M3's search is scoped to the extent of the **disposition author region** as G11's manifest locates it, and text in the prompt region is not a disposition for M3's purposes. Then add two fixtures to AC-DT-06: a generated skeleton with the prompt present and the author region **empty**, which exits non-zero on M3; and one with the prompt present and exactly one form in the author region, which exits 0 on M3. The alternative — declaring that M3 reads the whole file and relying on the prompt's wording not to instantiate either form — is available but weaker, because it makes the lint's correctness a property of a governed file this document does not control, which is the dependency G6 exists to keep out of the tool.

## N1 — non-blocking
Claim: AC-DT-02's structural class is **named but not delimited** — "a markdown structural delimiter or a punctuation mark" fixes no character set — so the exclusion is decidable at `---`, the case the directive names, and under-determined at its margins.
Location: specs/directive-tooling.md §6 AC-DT-02, the sentence defining *blank* and *structural*.
Evidence: Verified by reading. The clause names two categories and enumerates neither. "Punctuation mark" has a standard reading — Unicode general category P — and "markdown structural delimiter" has none; the two do not coincide, and the gap is not incidental: `|`, `>`, `=`, `+`, and `~` are Unicode category **Sm**, not P, and every one of them is a markdown structural character, so P alone under-covers the intended set and the union is stated nowhere in the document. The criterion's own illustrations — "a lone `#`, `|`, `-`, `>`, a fence, a table rule of hyphens and pipes" — are given as examples and are not written as the set.
Consequence: An implementer classifying a line that normalizes to `1.`, `**`, or `<!-- -->` gets a different answer under a strict category-P reading than under a loose "markdown syntax" one — `1.` contains a digit and is non-structural under the first, structural under the second. AC-DT-02's stated purpose is that stating the comparison "keeps two implementations of AC-DT-02 from disagreeing about what 'a line' means"; the comparison rule now achieves that and the class rule reopens one dimension of it. This is a **far narrower** residual than the one cycle 9's N1 named — that one reddened most correct implementations, and `---`, the demonstrating exclusion the cycle-10 directive names, is decided identically by either reading — which is why it is non-blocking. It is not nothing: a static check that two implementers build differently is a check whose red means two things.
Fix: Enumerate. Either name the character set outright, or state the rule as "every character is in Unicode general category P, or is one of `|`, `>`, `<`, `=`, `+`, `~`" — one sentence either way, and either makes the class as decidable as the comparison rule beside it. A third option, if the enumeration is judged to belong downstream: state explicitly that the set is fixed at the TRD stage and that `---` is the only member this document decides, which at least makes the openness visible rather than latent.
