## F1 — non-blocking
Claim: AC-LAND-01a's given restricts G1's branch-absent arm to a working tree behind the remote default branch, so the ordinary J1 state — a tree already at `origin/main` HEAD — has no criterion asserting the commit's parent.
Location: specs/bin-land.md §6 AC-LAND-01a (lines 280-283); §3 J1; §4 G1, first arm.
Evidence: Inferred by reading at this SHA, with the history verified by running. AC-LAND-01a reads "Given the named branch does not exist at the remote, and a working tree whose checked-out branch is behind the remote default branch, the invocation produces a commit whose parent is `origin/main` HEAD as of the invocation's own fetch". G1's first arm states no condition on the local tree — "Branch absent at origin — create it from `origin/main` HEAD" — and G1's closing paragraph applies to both arms without qualification: "In both arms the base is remote state as of this invocation's own fetch". AC-LAND-01a is the only criterion covering that arm; 01b and 01c both open "Given the named branch exists at the remote", and 02 through 10 state no condition on the tree at all (*observed*, read across all twelve criteria at this SHA). The clause was introduced at cycle 2, not this cycle: `git log -S` over the clause text names `7801f36` as the only commit that added it (*observed*), and the cycle-2 directive that authorised that revision dictated only "AC-LAND-01 rewritten to cover both arms" — the tree clause is the executor's wording, not Dave's (*observed*, docs/cycles/bin-land-spec-2-20260823T192131Z.md, B1).
Consequence: This is cycle 4's F1 in the other arm, and it is now the only place in §6 where a criterion's given is narrower than the goal arm it covers. A Test Designer deriving cases from §6 sets AC-LAND-01a up from a tree behind the default branch and has no criterion directing them at J1's ordinary state. That state is not hypothetical in this repository: an execution session's first act creates a worktree from `origin/main` and lands the directive file from it, which puts the tree exactly at `origin/main` HEAD — the state the given excludes (*observed*, the procedure this session itself ran). The parentage assertion for the create arm would therefore be tested only in the rarer state and not in the one J1 actually runs, which is the same failure cycle 4 corrected for J2. The narrowness is bounded to test derivation — G1's first arm governs both states normatively and §6 contradicts nothing — which is why this is non-blocking rather than blocking.
Fix: The same widening cycle 4 prescribed for 01b, applied to 01a — "Given the named branch does not exist at the remote, and a working tree at or behind the remote default branch". Two words. Deriving the two criteria's givens from one another is what keeps the pair symmetric, which is the property that made this visible.

Consequence: Documentation completeness, and narrower than it looks. The practical exposure is low: a session whose branch does not exist at the remote has not landed anything on it yet, so a local-only commit in that state is a stale tree rather than this session's work. This overlaps cycle 4's O1 without being the same item — O1 asks what the tool *does* to reconcile tree and base in the behind case; this asks whether the first arm refuses at all in the diverged case.

## On symmetry as the thing that found this

Worth one paragraph because the finding this cycle is a consequence of the fix rather than a defect in it, for the third cycle running — but in a different way this time. Cycle 3's F1 narrowed a criterion by adding a clause; cycle 4's F1 corrected that narrowing; and the correction made AC-LAND-01b and AC-LAND-01a asymmetric in a way they had not been since cycle 2, because 01b now says "at or behind" where 01a still says "behind". The asymmetry is what made 01a's given legible as narrow. It had been narrow for three cycles and two reviews read past it, one of them asserting in an *observed*-labelled field that it was not there. Nothing about the cycle-5 edits caused the defect; they caused it to become visible, which is the useful thing a paired criterion does. The general point for the remaining cycles: where §6 splits one criterion into siblings covering the arms of one goal, their givens should be written from each other, and a difference between them should have to justify itself. AC-LAND-01c's given differs from its siblings' for a real reason — it covers a different outcome — and says so. AC-LAND-01a's differs for no reason anyone recorded.
