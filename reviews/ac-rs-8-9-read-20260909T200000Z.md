## S-1 — blocking
Claim: a clone that ever ran `bin/install-hooks` cannot commit anything on this branch, and the branch retires the only tool that could undo it.
Location: `.git/hooks/pre-commit` (untracked, per-clone); the deletions of `bin/check-frontmatter` and `bin/install-hooks` in commit 58103ac
Evidence: verified by running — the first commit attempted by this review session was rejected with `ERROR: cannot locate the ai methodology home.` and exit 3. The managed shim's last line is `exec "$home/bin/check-frontmatter" --staged`, and it resolves `$home` by testing `-x "$candidate/bin/check-frontmatter"` over `$AI_METHODOLOGY_HOME`, `$top`, `$parent/ai`. fiducial is itself the methodology clone, so `$top` was the candidate that satisfied discovery; with the file deleted, no candidate does. The suite cannot catch it: `bin/tests/test_install_hooks.py` and `test_check_frontmatter.py` are deleted in the same commit.
Consequence: every commit fails, in any tree checked out at this branch, for any developer who has ever installed the hook. It is invisible from a clone with `main` checked out, because `$top/bin/check-frontmatter` still exists on disk there — which is why the executor's green run and the committed green log do not show it. `bin/install-hooks`, the only tool that manages the shim, is deleted by the same commit, so there is no supported way to remove it.
Fix: this is a change-package gap, not a code gap — the branch cannot touch an untracked file, and must not keep a stub of retired tooling to satisfy it. AC-RS-8 is literally satisfied: it requires that "no hook is installed by any tool in the tree", and no surviving tool installs one. The AC-RS-8/AC-RS-9 change package must therefore state the migration step in these words: "If you ever ran bin/install-hooks, remove .git/hooks/pre-commit." A fresh clone that never ran `install-hooks` is unaffected.
