## B1 — blocking
Claim: M8 is now a disjunction over the filename alone, but §4 states the pattern is determined by the generator's mode and selector, and the lint has no mode or class signal to determine it with — so the check cannot enforce the rule the document says it enforces, and a general-mode directive named `<anything>-directive.md` passes M8 without a timestamp.
Location: specs/directive-tooling.md §4 M8 row and the "M8 admits three patterns" block, second paragraph; §6 AC-DT-06 M8 clause; §2 "Primary actor — the execution session"; §4 M5 Decision-qualification column.
Evidence: Verified by reading, and by running. §4 states the disposition as "the pattern is **determined by the generator's mode and, in the cycle mode, by the selector**, not chosen freehand by the author. The cycle mode emits the AC-CO-1 form its selector names … the general mode emits the timestamp form." M8's element text carries none of that: it reads as three alternatives over the filename, "exactly one of three patterns … No fourth pattern passes." Nothing in the document gives the lint a mode or class input — §2 has the execution session run `bin/check-directive` against the directive file it just wrote, §5's "one directive per invocation" says the same, and M5's Decision-qualification column states the general principle in the document's own words: "no class exemption exists for the lint to carry." The governed source M8 cites is itself conditional — `skills/directive-authoring.md` @ `83b60511` says the timestamp form applies "**except** a reviewer-gated cycle directive" — and M8 drops the exception's condition while keeping its consequence. Verified by running that the widening is not theoretical: of the 97 `.md` files in `docs/cycles/`, 26 match pattern 3, and pattern 3 admits every one of them without reference to whether it is a reviewer-gated cycle directive.
Consequence: The lint stops catching the failure mode M8 was written for. An author in a degraded decision session — the actor §1 names — writes a general directive, names it `pass3-holdout-fix-directive.md`, and M8 exits 0, because the name ends in `-directive.md`. The skill that governs the author says that name is wrong; the lint that gates the executor says it is fine. That is a lint permitting what its own cited source forbids, and unlike G6's prohibition (which forbids the lint being *stricter*) the document has no rule against it and does not acknowledge it. Downstream, a Test Designer writing from §6 has no fixture that can distinguish the two cases, because AC-DT-06's M8 clause names five fixtures by filename and none by mode. And §5's third signal — "invariant text stops contradicting itself," measured by recount over directives authored after adoption — now runs against a check that rejects 1 of 97 names.
Fix: Three options, and the choice is Dave's. (a) M8 becomes conditional rather than disjunctive, and the directive file carries a mode or class marker the lint can read — which reopens Q5's territory, since it is the same "what does the file itself declare" question route and model raised. (b) M8 keeps three unconditional patterns and §4's mode-and-selector sentence is deleted, the document stating plainly that the lint accepts any of the three from any mode and that enforcing the mode-appropriate one is the generator's job and not the lint's — the honest version of what the text currently checks. (c) Pattern 3 is tightened so it cannot swallow general-mode names — but AC-CO-1 puts no constraint on `SLUG` (see N1 below), so there is no property available to tighten on. (b) is the smallest change consistent with what M8 can actually decide; (a) is the only one that keeps the disposition's stated intent.

## B2 — blocking
Claim: N1's time-component requirement makes M8 stricter than the governed text it derives from, which G6 forbids and AC-DT-13 asserts of no element — so AC-DT-13's sentence "Every element M1–M8 satisfies this as written" is now false, and §7's "Not accepted" list forbids what M8 now does.
Location: specs/directive-tooling.md §4 M8 row; §4 G6; §6 AC-DT-06 M8 clause and AC-DT-13; §7 "Not accepted", final item.

M8's cited source, quoted in its own Derived-from column, says only "the timestamp in ISO 8601 basic format." ISO 8601 basic admits a calendar date alone — `20260823` is a well-formed ISO 8601 basic date — so a governed reading of that sentence does not require a time component. M8 now does: "carrying **both** a date and a time … A trailing date with no time component is **not** a timestamp for this check." The rule is dictated (*told* — the cycle-5 directive's N1) and the document says so, but a dictated disposition in a directive file is not one of G6's governed sources; G6 names `docs/global-context/core.md`, `docs/global-context/decision-layer.md`, `skills/directive-authoring.md`, and `decisions/log.md`, and none of the four states the time component. Consequence: The document contains a criterion (AC-DT-13) that its own element table falsifies, and a risk item marked "Not accepted" that its own element table instantiates. An implementer building to §6 has to satisfy AC-DT-06's date-only failing fixture and AC-DT-13's no-ungoverned-requirement criterion at the same time, and cannot. A reviewer auditing M8 against G6 — which AC-DT-13 says is how the criterion is verified, "by review of the requirement table against those files" — reaches a defect. This is structurally identical to the M3 situation cycles 1 through 3 tracked, where an element outran its governed source and the resolution was an expedited amendment to `skills/directive-authoring.md`; the difference is that M3's gap was disclosed and held open, and this one is asserted closed.

(b) Keep M8's rule and state the exception explicitly: AC-DT-13 and §7's "Not accepted" gain a named carve-out saying the time component is a dictated narrowing of "ISO 8601 basic" that no governed file yet states, with the amendment scheduled — which is cycle 3's M3 treatment, and is honest but reopens a residual cycle 4 closed. (c) Drop the time-component rule, admit the date-only form, and move the count from 1 non-conforming to 0. (a) is the only one that leaves the document internally consistent without a standing residual.

## On what the revision got right, and what the widening cost

All four dispositions landed, and two landed beyond the letter. N3's rewrite is
the strongest thing in this cycle: the cycle-4 precedence clause is deleted
rather than qualified, the replacement binds in both directions, and it is
already load-bearing — the "fourth filename branch" block routes to it, and O3
above is the first use of it as a check rather than a promise. B1's execution
quotes AC-CO-1 whole for the first time, anchors patterns 2 and 3 on the
criterion itself rather than on a skill sentence that restates half of it, and
states the cost of the widening in the same paragraph as the widening — 29
non-conforming to 1, said plainly, not buried.

What sends this to `changes-required` is that both blocking findings are in that
same widening. M8 has been made to admit AC-CO-1's second branch, but the
document describes the result as mode-determined while writing it as a check on
the filename alone, and the lint it specifies has no mode to determine anything
with — so the pattern that was added for the cycle mode is available to every
mode, and the timestamp requirement becomes optional for any author willing to
end a filename in `-directive.md`. Alongside it, N1's time-component rule makes
M8 stricter than the sentence it cites, which is the one thing G6 names as a
defect and AC-DT-13 asserts of no element. The two pull in opposite directions —
one makes M8 weaker than its source, one makes it stricter — and they are both
consequences of deciding M8's shape one branch at a time across five cycles. The
document is now correct about *what* the contract requires; it is not yet
coherent about what the lint can decide from a filename with no other input, and
that is the question B1's three options put to Dave.
