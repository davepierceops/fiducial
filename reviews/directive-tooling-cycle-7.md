## N1 — non-blocking
Claim: §5's third outcome survived the removal of "concurrently-live", but its baseline is stated in **directives** while its mechanism counts **contradiction instances**, and the set it now measures starts empty — so the comparison the bullet specifies still cannot be performed.
Location: specs/directive-tooling.md §5, third outcome (the `Baseline:` and `Mechanism:` clauses, and the cycle-7 narrowing paragraph).
Evidence: Verified by reading. The baseline reads "the merge-mechanism contradiction across eight directives and their successor", which is **one** contradiction implicating **nine** files; the mechanism reads "a recount of **contradiction instances** over directives authored after adoption, read against that baseline of nine". Nine is a count of directives; the recount produces a count of instances; the bullet reads one against the other. The narrowing paragraph added this cycle inherits the phrase unchanged ("counted against the nine-directive merge-mechanism baseline"). Separately, the narrowing scopes the count to post-adoption directives, a set that is **empty at adoption** and grows from zero, so the first recount necessarily returns 0 against a baseline of 9 whether or not the tools work.
Consequence: The outcome is not falsifiable as specified, which is the same property cycle 6's N2 raised about the same bullet through a different term. A reader asked whether this outcome was achieved gets 0-of-9 on day one and cannot distinguish "the tools worked" from "no directives have been written yet"; a reader asked a year later cannot tell whether a count of 2 instances is better or worse than a baseline expressed in files. Core rule 13's reproducibility discipline is what this fails, and §5 is the section the Spec Reviewer's PRD checklist requires to name the signal, the baseline, and the mechanism — the first and third are now clean, the second is not.
Fix: One clause fixing the unit, and it is Dave's choice which: (a) restate the baseline as **one** contradiction instance implicating nine directives, and the measurement as instances, so both sides are instances; (b) normalize — instances per hundred directives, or per cycle — so the growing post-adoption set is comparable to a fixed pre-adoption corpus; or (c) state the measurement as a **first-recurrence** check ("no post-adoption directive contradicts another"), which needs no baseline at all and is the cheapest thing the recount can actually decide. This was not patched in-cycle because choosing among the three is a measurement decision, not a wording repair.

Claim: Pattern 3's boundary is now stated as "any slug the preserved contract can emit", which does not decide whether a path separator is admitted — so pattern 3 is still implementable two ways, and the strict implementation reproduces cycle 6's B1 shape one level further down.
Location: specs/directive-tooling.md §4 M8 row, pattern 3; §4 "Pattern 3 states no character class"; §4 "Provenance of the recount"; §6 AC-DT-06, M8 clause.

## On the first cycle that closes without a blocking finding

Cycle 6 sent this document back with two blocking findings that were both
consequences of executing cycle 6's own dispositions: a character class M8 had no
authority to state, and a residual §4 named but AC-DT-08 did not disclose. Both
are closed, and the way B1 was closed is the part worth Dave's attention. The
three prior times an element outran its governed source, the resolution was an
expedited amendment to the governed file — three amendments to
`skills/directive-authoring.md` in this effort. This time the disposition went the
other way: **delete the requirement**. That is cheaper, it needs no agreement from
anyone else, and it is the correct branch when the requirement was never needed —
which the recount proves, because the classification with the class and without it
disagree on no file in a 99-file corpus. §7 now records both routes as admissible
under G6, which is a better statement of the rule than "amend the source" was.

What this cycle did not do is find a new clause-sized leftover of the kind the
last four cycles each produced. Both non-blocking findings predate the
dispositions: N1's unit mismatch has been in §5's third outcome since cycle 1 and
was hidden behind the term cycle 6's N2 found and cycle 7's N2 removed — removing
the term is what exposed it. N2's path-separator boundary has been in pattern 3
since cycle 5 licensed it and was hidden behind the character class, which
excluded separators as a side effect of excluding everything but lowercase and
hyphens; dropping the class is what exposed it. Both are the same phenomenon: the
narrowing dispositions removed the wrong answers that were standing where the
missing answers should be. That is what convergence looks like from the inside,
and it is the argument for taking the two remaining items as one more dictated
disposition rather than as a signal that the document is unstable.

The verdict is `ready-with-findings` rather than `ready` because N1 leaves one of
three user outcomes unfalsifiable as specified and N2 leaves one of eight
mechanically-checkable elements implementable two ways — neither blocks agreement,
both should be closed before a TRD derives from them. It is not `changes-required`
because neither is a contradiction with a parent artifact, neither makes a
statement in the document false, and neither would be resolved by this session
reinterpreting a disposition. And the independence caveat at O1 applies to this
verdict more than to any prior one: it is the first pass this document has cleared,
returned by the session that wrote it.
