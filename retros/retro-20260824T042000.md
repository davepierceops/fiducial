## Interpretation
- (2) The constraint/instruction check as practiced compares the Do-not block against the instruction list but not against the *sweeps* the directive mandates; the sweep is an instruction whose reach is computed at execution time, which is exactly where a static read misses it.
- (3) Derived context artifacts (the bundle) are a second source of truth that goes stale silently; Core rule 8 ("read; do not recall") was followed against the repo but the bundle smuggled a stale fact in anyway.
- (5) Full-file connector writes have a practical size ceiling; frontmatter-only operations need a transport that doesn't round-trip the whole document.
- (6) Enumerated gate expectations in directives are snapshots; concurrent workstreams move the baseline under them.
- (7) Scope-bounded confirmation gates are cheap and sufficient when the bound is dictated by the human, not chosen by the reviewer.

## Durable insights
- When emitting a scoped Do-not, name the sweep exemption explicitly ("the Core rule 13 sweep may reach X") or scope the Do-not to the named fix.
- State accepted test-failure sets by reference or with a baseline commit, not by fixed enumeration.
- The flip-by-command-block pattern (clone, guarded rewrite, push, connector verify) is reusable and should be the standing mechanic until tooling exists.
- Confirmation-scoped gates earn their keep; the bound must come from Dave.

## Candidate methodology changes
- skills/directive-authoring.md: extend the constraint-check rule to cover mandated sweeps, not only listed instructions (input to the next CQR cycle on that file, alongside deferred F-1/F-2/F-3).
- Directive gate-expectation language: cite a baseline commit for the accepted failure set (candidate for the same cycle, or for bin/check-directive's invariant list).
- Regenerate the project context bundle after any rename touching its file set; consider stamping bundles with a staleness warning against `git log --diff-filter=R`.
- A remote-flip tool or documented command-block pattern for frontmatter-only status transitions (relates to the existing bin/flip-agreed; the gap is the remote/decision-session path).
