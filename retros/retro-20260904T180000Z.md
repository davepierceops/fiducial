## Interpretation
- (1) The baton is a pointer set, not a scope statement. Reading the file and the tracker entry it pointed at changed the directive's scope before drafting; a directive written from the baton alone would have fixed half the defect.
- (2) A directive pinned to a base ref is idempotent as long as the base holds; "did I run this" is answered by origin in two commands. Worth stating in the authoring skill so a successor does not re-draft.
- (3) A tool that restores state on a failure signal it did not verify is the same defect class as a session retrying a write it did not read back. The rule already exists (Core 12); the tool does not follow it. The executor's recovery was correct at every step after the mistake, and the mistake itself was the tool's false report leading a reader to a false conclusion — the report shape "restored" implied "nothing landed".
- (5, 6) `status: agreed` has been carrying two different claims: "a reviewer read this whole" and "a reviewer read the diff that last touched this". The frontmatter cannot distinguish them; only the artifact's scope line can. The methodology has been describing the second as if it were the first. Dave's instinct that dedup "hasn't really happened" was right, and the tree said so once asked the right question.
- (7) Three failures stacked: an author miscount, an executor write that stopped short, and a read-back that checked structure instead of content. The first two were caught only because the third was tightened. Landing verification by heading is the same false comfort as landing verification by tool response.
- (8) The register rules — lead with the point, one question at a time — are load-bearing for Dave specifically, and a long correct answer costs more than a short incomplete one. The three follow-up questions were all about vocabulary I had used without defining.
- (9) Parallelism is a property of the artifact class, not of the tooling: read-only, one-new-file gates parallelise; body edits to shared files do not. That classification is worth writing down once.
- (11) Rulings recorded only in the tracker are findable by grep but not by DEC ID; the decision-log policy says the log is where a decision resolves to. Two of this session's rulings (fold; sequence of corpus pass after selection build) will be cited later and have no ID.

## Durable insights
- Read-back after any executor write compares the landed text against the dictated text, byte for byte, before the PR opens. Heading presence is not evidence of content.
- A tool or session that restores state on an apparent failure must read HEAD first; the same rule that governs retries governs rollbacks.
- `agreed` needs a companion axis: whole-read or diff-read. Until it has one, "reviewed" claims about the corpus are made per artifact scope line, never per frontmatter.
- Directives that enumerate state the count or omit it; a stated count that disagrees with the list becomes the instruction.
- When Dave asks "where are we", compute the answer from frontmatter and artifact scope lines, not from the baton's narrative.
- Whether work can be fanned out is decided by what each unit writes; gates fan out, fixes to shared files do not.

## Candidate methodology changes
- skills/directive-authoring.md: a read-back rule for the decision session — dictated text is compared verbatim against the landed file before a PR is opened; and a counting rule — enumerated items carry no count, or the exact count.
- bin/flip-agreed (specs/directive-tooling.md or its TRD rider queue): on non-zero commit exit, read HEAD before restore; emit a distinct diagnostic when the commit landed and only the tree was restored.
- policies/document-metadata-policy.md: consider a `review-scope: whole | diff` value on `last-reviewed`, or a rule that a reconciliation artifact cannot satisfy `agreed` for a document whose body it did not read — input to the queued cycle, not a decision.
- policies/decision-log-policy.md or decision-layer rule 10: state that a sequencing or scoping ruling on a governed document gets a DEC entry when a later cycle will cite it, not only when it changes methodology text.
- docs/global-context/core.md or the operating model: a sentence on sub-session spawning by an execution session — permitted or not, and under what disposition — before the corpus-pass program opens.
- skills/directive-authoring.md: a note that a pinned, unrun directive is re-used verbatim if origin shows its base unchanged and its branch absent.
