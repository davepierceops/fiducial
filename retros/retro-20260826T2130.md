# Retro — fiducial — 2026-08-26

## Context
A Chief of Staff session that logged two pending decisions (DEC-000200, DEC-000210), then ran a corpus deduplication: rule extraction into a register (878 rows), semantic clustering (77 clusters, 8 divergent), Dave's rulings on the 8 divergences, a two-cycle Context Quality Reviewer gate over the whole branch diff, and agreement flips for eleven documents. Six execution sessions, six PRs, main advanced from 2f5323d to 6e80742.

## Evidence
1. Dave asked "how many lines" before deciding anything; the answer (8,946, 63% from three mistagged specs) was obtained by cloning the public repo in the CoS sandbox and running `bin/bundle` — no executor needed.
2. Dave's hypothesis — duplication would be semantic, not greppable — held: 220 of 878 rules were restatements; grep found none of the 8 divergences.
3. The Pass 1 executor reported that its own manual verification (10 random rows read by eye) would have passed while 101 line citations were wrong; only an automated re-locator caught the drift.
4. Pass 2 clustered from the paraphrase columns and confirmed against `source`; verification dissolved 0 clusters and split 2.
5. The rulings directive said "do not flip status"; the pre-commit hook flipped nine agreed files to in-review; the executor let it stand and reported it rather than bypassing with `--no-verify`.
6. Dave chose one CQR gate over the nine-document branch diff instead of nine per-document cycles; the CQR ran it, named the branch in the artifact stem, and recorded the deviation in `Scope:`.
7. Cycle 1: 3 blocking, all inside the wording Dave dictated for C001 (whole-session stop; "waits for Dave" not an executable act). Cycle 2: no blocking.
8. The worktree command in the first two directives was wrong (`--no-track` without `-b`); the executor recovered and reported the working form.
9. The GitHub connector timed out twice (4 min each) while an executor was active; the hung `create_pull_request` did not create a PR; restart fixed it.
10. A flip block pushed directly to main and was rejected by branch protection; a second block moved the commits to a branch; the PR merged clean.
11. Every executor report labelled claims observed/inferred/told without being reminded mid-session.
12. Dave's inputs were mostly one character: "c", "b", "a", "y", "1", "ok", "go".

## Interpretation
- (1, 2) A cheap measurement before a plan changed the plan: the "dedup" Dave asked for was two things — a tagging fix worth 63% and a semantic pass worth ~25% of the remainder — and only the measurement separated them.
- (2, 4) Extract-then-cluster works because it moves the comparison from prose to a shape (binds/verb/condition); the frontier model was needed only for pass 2, on 878 rows, not on 3,300 lines of prose.
- (3) Verification by reading does not catch position drift. A directive's "sample 10 and read" check is weaker than it looks; a mechanical re-locator should be the stated check for any position-bearing artifact.
- (5, 6, 7) The corpus's own rules were stronger than the directive where they conflicted: the hook overrode "do not flip," the CQR flagged Dave's own dictated wording. Both are the system working; the directive author (this session) was the weak link twice.
- (8, 10) Both git-mechanics errors were mine and both were the same kind: a command written from memory against a repo whose constraints (branch protection, worktree syntax) were observable. Read-before-recall applies to shell blocks as much as to governed text.
- (9) Connector contention with a live executor is now a repeated pattern; the sandbox clone is a reliable read path during it.
- (11, 12) The register of terse inputs is the system at its best: every one-character answer landed in a committed decision record within the same session.

## Durable insights
- Measure before planning a cut. Line counts per file took thirty seconds and reordered the whole plan.
- Rule extraction into a fixed-shape register is the reusable dedup primitive; the register is also the seed of the row-granular bundle model.
- A multi-document reconciliation gate — one CQR artifact over a branch diff, stem named for the branch — is a working pattern and cheaper than per-document cycles when the edits are one decision set.
- Directives should say "status flips the hook makes are expected," never "do not flip status," for any content edit.
- Position-bearing derived artifacts need a mechanical verification step named in the directive.
- The CoS sandbox can clone the public repo and run `bin/*` read-only; use it for measurement and when the connector is contended.

## Candidate methodology changes
- `skills/spec-review-cycle.md`: add the reconciliation-style multi-document gate as a sanctioned shape, with the artifact stem naming the branch and `Scope:` recording the deviation.
- `skills/directive-authoring.md`: (a) working-tree command form `git worktree add --no-track -b <branch> <path> origin/<ref>`; (b) "hook flips are expected" boilerplate for content-edit directives; (c) for any artifact with line or position citations, require a mechanical re-check, not a read sample.
- `skills/command-blocks.md` or the sandbox notes: main is branch-protected; a block never pushes main; flips go to a branch and the CoS merges.
- Sandbox docs: connector contention while an executor is active — read from a sandbox clone; check `list_pull_requests` before re-creating after a timeout.
- Consider a `bin/rules` (or `bin/state` extension) that regenerates the rule register from the corpus, so the register is computed state rather than a one-off artifact.
