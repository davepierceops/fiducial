## Interpretation
- (1, 2) A baton that names one workstream as the next task can be overtaken by a parallel chat the baton author did not know about; the CoS should establish what is running elsewhere before proposing writes.
- (3, 5) Two Claude Desktop chats sharing the GitHub connector contend; reads degrade to timeouts while the other chat's executor is active, and main keeps moving. Executor-run directives and Dave-run command blocks are the contention-free lanes.
- (7) The rule-8 failure had a specific shape: a tool call failed, and the CoS fell back to a log entry (a record of intent) as if it were a record of state. The sweep caught it only because the sweep ran; a directive without a sweep would have merged the false statement.
- (6) The directive-form failure was invisible to the author and obvious to the reader — the same class as the command-blocks skill's "copyable in the surface that delivers it."
- (10) Baton loose-end lists can carry items that the governing spec has already re-timed; the item's own source must be read before it is dispatched.

## Durable insights
- Before authoring any statement about what tooling exists, read the tree (`git grep` / directory listing), never a decision-log entry. When the connector is unavailable, put the read in the directive as a STOP condition rather than assuming.
- A fenced paste block cannot contain a ``` fence. Inner blocks use `~~~` plus a FENCE NOTE; this belongs in the directive-form rule.
- When a second chat is active on the same repo: no connector writes, executor-run directives only, and every branch-cut pins a SHA because main moves between turns.
- Sandbox `git worktree add` from a remote ref needs `--no-track`.
- A directive-level sweep instruction may be scoped "as a report" when the Do-not is narrower than the sweep's reach; saying so resolves the constraint/instruction conflict the prior retro flagged.
