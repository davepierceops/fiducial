## Interpretation

- (2) The "landmine" label had been spent on nothing often enough that Dave
  now reads it as noise; the decision-layer rule needs the test the tracker
  already proposes.
- (3) Building the artifact answered a confidence question better than any
  stated confidence could, and surfaced a workflow simplification the design
  missed. Prove the mechanism before writing the rule that depends on it.
- (4, 5) Compressing a design into one y/n hides the sub-questions; when Dave
  slowed it down, two of the resulting decisions were his own proposals and
  better than the compressed one.
- (6, 7) Two defect classes in freshly drafted role documents — human-register
  prose and negated rules — were both caught by Dave on first read, not by
  the drafter. Both are checkable; neither is in the rubric as an affirmative
  test.
- (8, 9) Reading the governing text before drafting against it found a
  nonexistent rule and seven ungoverned criteria. Core rule 8 applied to
  drafting, not just to state.
- (12) A connector write is a hook bypass; the author is the only check.
  Every connector-written in-scope file needs the full required field set
  stated explicitly and a `check-frontmatter --all` before merge.
- (13, 15) Executor directives with delta text, and plain notes between
  decision sessions, both worked first time. Neither needs a new term.

## Durable insights

- Prove the mechanism on the real artifact before writing the role that
  depends on it; the test file is cheaper than the argument and finds what
  the argument would not.
- State a rule as a test the agent runs per instance, not as a prohibition
  it must remember: "two copy editors from the same authority would make the
  same change."
- Walk every criterion to the pass that checks it before agreeing a criteria
  document; a criterion with no reviewer is a wish.
- Solve distribution for the user with the fewest tools (a document and a
  chat) and the artifact-location question answers itself.
- After any connector write of an in-scope file, an executor runs
  `check-frontmatter --all` before the PR merges.

## Candidate methodology changes

- Review rubric: add an affirmative test that every rule in a role or skill
  is an instruction in the second person to the agent reading it (criterion 5
  states it as a description); add a test that each prohibition carries or is
  replaced by a per-instance test.
- Core: a role that names a document absent from its context asks for it
  before acting on what it governs, and never proceeds from memory of it
  (already in the three writing roles).
- Decision layer rule 3: the landmine test already on the tracker — something
  Dave would act on differently if unnamed — with the label dropped from
  chat register entirely.
- Remote-write verification policy: connector writes of in-scope files
  require the full required frontmatter field set stated explicitly and a
  `check-frontmatter --all` run before merge; the hook does not fire.
- `roles/writer.md` was rewritten this session; the same human-register
  defect likely exists in other roles written before the rubric's criterion 5
  and is worth one audit.
