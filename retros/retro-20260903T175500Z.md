## Interpretation
- (4) A bundle is a snapshot; a directive that cites rule numbers from it is authored from recall, not from a read. Core 8 already forbids this; the failure was treating a bundle in context as equivalent to the file at main. The gate caught it because the Reviewer read the companion at its SHA — the companion discipline worked as designed.
- (2, 5) The fence rule landed in the same cycle that needed it; the transport of the directive that added the rule already obeyed the rule. That is the first observed instance of the skill governing its own delivery.
- (6) `bin/flip-agreed` accepts either SHA form; the policy and precedent fix the document SHA. The tool does not enforce the distinction, so the decision session must.
- (3, 10) `bin/directive` cycle mode writes into the clone it runs in and leaves an untracked file; the tool's usage surface has three refusals that are only learned by tripping them. Cheap friction, but recurring across sessions.
- (8) The sandbox false match is now a three-occurrence pattern across two sessions; the rider queued on OPEN-ITEMS is the right home.
- (9, 11) Read-back after every write, and one question in the whole session, produced a three-PR cycle with no relay wait on Dave. The serialization cost was executor turnaround only.

## Durable insights
- Cite rule numbers, counts, and section names from the file at main at the moment of drafting, never from a bundle or a prior directive, even when the bundle is in context.
- A flip pointer's SHA is the reviewed document's content commit; probe with `--no-commit`, but the probe's acceptance is not confirmation of the correct form.
- Converting skeleton fences to `~~~` before pasting is a fixed step of directive emission, not a judgment call.

## Candidate methodology changes
- `bin/directive`: emit `~~~` for the disposition-prompt inner fences directly, so the skeleton conforms to the command-blocks fence rule without a post-generation step (directive-tooling TRD rider queue).
- `bin/flip-agreed`: reject or warn when the `--review` SHA is not the reviewed document's last content commit (or does not match the artifact's Reviewed: line) — closes the gap in Evidence 6.
- `bin/check-directive`: a check that any "rule N" citation of a companion resolves against the companion at its cited SHA — would have caught Evidence 4 before dispatch. Candidate M-rule for `specs/directive-tooling-trd.md`.
- `bin/directive` cycle mode: write to stdout by default, or clean up on `--write`-less runs, so a sandbox clone does not accumulate untracked directive files (Evidence 10).
