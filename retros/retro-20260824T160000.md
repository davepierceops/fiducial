# Retro — fiducial — 2026-08-24

## Context

A hub session opened on a baton from bin-land-trd cycle 3 and ran roughly fifteen
hours. It carried the TRD review series from cycle 3 to cycle 9, abandoned the
review loop mid-series on Dave's judgment, ran a spec/test convergence using
Claude Code subagents, agreed the spec and its suite together, and implemented
`bin/land` to green. The session's largest output was not `bin/land` — it was a
set of methodology changes Dave decided in response to watching the review loop
fail to converge.

## Evidence

1. Four consecutive re-gates (cycles 4, 6, 8, and the cycle-8 readiness
   assessment) each returned exactly one blocking finding. The count was flat
   across the series.
2. The blocking finding's blast radius shrank monotonically: three sections
   disagreeing (cycle 4), one table row's two columns (cycle 6), one paragraph
   (cycle 8).
3. Cycle 8's blocking finding was a sentence that was true when written and made
   false by the ceiling decision taken in cycle 7.
4. Cycles 5, 7 and 9 each took new design decisions inside cycles whose stated
   purpose was disposing findings: collapsing three sections to one, reversing
   the emission floor to a ceiling, and making §5.3's prose non-normative.
5. Every reviewer report in the series carried the same provenance line: claims
   about what the tool would emit were *inferred by reading*, because no
   implementation existed.
6. The two most decisive findings in the review series came from reviewers
   running actual git probes — the J2 success path carrying no prior branch, and
   the FM-3 refusal biconditional holding on every path.
7. Nine review cycles produced no tests and no code. At the point Dave stopped
   the loop: 1,383 lines of specification, zero tests, zero implementation.
8. Dave: "it's time to quit fucking around with specs and start writing some
   stuff."
9. One round of test authoring produced eight findings, three of which required
   design decisions no review cycle had surfaced: FM-9's reachability, FM-5 and
   FM-6 being indistinguishable in the report, and FM-7's exit code.
10. FM-9's unreachability was established by construction — a remote
    `post-receive` that resets the ref lands as FM-8 — not by argument. §4.3 had
    argued it on paper for cycles without anyone acting on it.
11. Cycle-8's N2 finding (an acceptance criterion untestable on six of ten
    cases) took eight review cycles to surface. A Test Designer hit it in its
    first round, because it sat down to write those cases and could not.
12. Claude recommended YAGNI on distinguishing FM-5 from FM-6. Dave overruled on
    domain knowledge Claude did not have: LLM agents attempting a landing with
    nothing staged will not be a rare case.
13. Four directives Claude authored contained factual errors that executors
    caught rather than executed: the wrong role (Coder for spec authorship), a
    false premise about a test helper's purpose, two clauses pulling to
    different answers on the diagnostic code set, and a `last-reviewed` pointer
    that would have failed `bin/flip-agreed`'s gate.
14. Claude emitted a paste block with an open question after it. Dave had
    already executed the block before reading the question.
15. Claude produced two empty turns across the session, both after long
    execution reports.
16. The implementing session ran nine mutations against its own green
    implementation. Eight were caught by the suite. One survived: deleting
    §3.2 step 7's `git reset --mixed <base>` left all 440 tests green, revealing
    that AC-LAND-02 ships untested.
17. Subagent orchestration failed on the first attempt because Claude Code's
    project root was `.claude/agents` — Dave had `cd`'d there to show Claude the
    README. The session refused the available workaround (two `general-purpose`
    dispatches with full tools each) because it would have given the test
    designer edit rights over the spec.
18. `git worktree add` stopped working mid-session; the sandbox now denies
    writes to `.git/`. Every directive in the session specified a worktree.
    Executors improvised clones and reported the deviation.
19. `context-sets/base.md` does not exist in the repository, though `CLAUDE.md`
    lists it as required reading. It is the likely cause of two long-standing
    test failures.
20. Agreeing the TRD required stretching the expedited path, which
    `policies/document-metadata-policy.md` frames for small doc-only changes.

## Interpretation

**The review loop was not failing to converge; the target was moving.** (1, 3,
4) The flat blocking count read as stagnation, but the shrinking blast radius
(2) says otherwise. Each cycle's finding was largely manufactured by the
previous cycle's design decision. Claude authored every one of those directives,
so the churn was a discipline failure in directive authoring, not a defect in
the review mechanism.

**Reading has a ceiling, and the series hit it several cycles before anyone
noticed.** (5, 6, 7, 9, 10, 11) Every claim in a spec about a program that does
not exist is inferred. The findings that actually moved the design came from
touching reality — a probe, a constructed remote, an attempt to write a test.
The corpus had exactly one pre-agreement validation instrument, and it was the
weakest one available for the questions that remained.

**Test authoring is a mechanical check on specification quality.** (9, 11) A
criterion that cannot be turned into a test that fails for the right reason is
defective, and that is discoverable in minutes rather than cycles. This is not a
subtle instrument; it was simply absent from the sequence.

**Domain knowledge Dave holds and Claude does not is decisive at exactly the
points that look like judgment calls.** (12) Claude's YAGNI recommendation was
sound given its premises and wrong given the real consumer. The pattern:
Claude's design instincts are calibrated on a generic caller, and this tool's
caller is an LLM agent whose failure modes Dave has watched.

**The stop-and-surface discipline is carrying real weight.** (13, 16, 17, 18)
Four directive defects, one surviving mutation, one refused workaround, one
broken sandbox assumption — all surfaced rather than absorbed. The executors are
more reliable than the directives handed to them, which is an uncomfortable
inversion but a working one.

**Verification of one's own green is a distinct step from producing it.** (16)
The implementing session's mutation testing found a hole nothing else would
have. Green from a suite that has never been shown able to fail is a weaker
claim than it reads as.

## Durable insights

- **Spec and tests open simultaneously, converging, then flipped together.**
  Neither gates the other; findings flow both ways. This replaces spec-first
  then derive-tests. Evidence: (9, 11).
- **A re-gate cycle disposes findings and takes no new design decisions.** A new
  decision opens its own cycle. Evidence: (1, 3, 4). This single rule would have
  prevented most of the nine-cycle series.
- **When a review series' findings stop shrinking in kind rather than count,
  change instrument rather than iterating.** Count alone is a misleading
  convergence signal (1, 2).
- **A mutation that survives a green suite is a coverage finding, and the agent
  that wrote the code should not write the test that closes it.** (16)
- **Empirical questions about an unbuilt tool are answerable before building
  it** — by constructing the situation and watching, not by reading harder (6,
  10).
- **A paste block executes on sight.** A question in the same response is
  answered by the execution, not by Dave (14).

## Candidate methodology changes

Phrased as inputs to a future review cycle, not as decisions.

1. **Amend the change flow** so spec and test authoring are concurrent and
   pre-agreement, with a joint agreement gate. Touches
   `operating-model.md` (steps 1–4) and
   `context-sets/spec-and-change-discipline.md`.
2. **Add a rule to `skills/spec-review-cycle.md`**: a re-gate cycle disposes
   findings and takes no new design decisions; a new decision opens its own
   cycle.
3. **Make test authoring a spec gate.** A criterion that cannot be expressed as
   a test that fails for the right reason is a defective criterion, surfaced
   before agreement.
4. **Introduce a spike step** — time-boxed, throwaway, permitted before
   agreement, output is findings only and never shipping code. The corpus's
   absence of one is why another review cycle was the only legal move.
5. **Define an orchestrator role.** Every convergence directive this session
   read "Role: none established" and carried constraints inline.
   `roles/orchestrator-agent.md` is superseded and frozen;
   `roles/chief-of-staff.md` explicitly does not execute.
6. **Reconcile the expedited path with practice**, or state the wider case
   explicitly. It was stretched to agree a 1,400-line TRD (20).
7. **Add mutation testing to the definition of done**, or state why green
   without it is sufficient (16).
8. **Correct the sandbox companion documents**: `git worktree add` no longer
   works, and the keychain noise appears on `clone` and `ls-remote` as well as
   `fetch` and `push` (18).
9. **Resolve `roles/architect-agent.md`'s self-contradiction** on session kind.
10. **Create `context-sets/base.md`** or remove its requirement from
    `CLAUDE.md` (19).
