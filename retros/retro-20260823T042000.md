# Retro — fiducial — 2026-08-23

## Context

One decision session ran the Pass 1 reconciliation re-gate end to end: triage of the 47-finding reconciliation artifact, six fix directives, five confirmation cycles, nineteen PRs (#127–#149), converging 47 → 15 → 6 → 2 → 1 → 0. Pass 1 closed with the corpus clean at 12ecaeb. Thirteen decisions (D1–D13) were made in triage; most reversed or went beyond the reviewer's proposed fixes.

## Evidence

1. The reconciliation cycle found 47 findings. The first fix directive closed 44 and introduced 12 new ones; the second confirmation found 6; the third 2; the fourth 1; the fifth 0. Five of the six fix directives were needed to clear residue from the first.
2. Of the 12 new findings after fix-1, at least 9 were the decision session's misses, not the executor's: D5 dictated in three files and not the fourth (operating-model.md, all-roles); D4 dictated for two files and not baseline-measurement; the CQR-gates-agreed clause dictated without the metadata policy's two reviewer-less paths; the no-release-gate sentence dictated into two files in one bundle; "Expected-delta item" named as the home of post-change evidence.
3. Fix-1 changed a policy the tooling reads (audience-value rule, README glob) without naming the tooling; bin/check-frontmatter and three tests went red; the executor committed with --no-verify and surfaced it. Fix-2 was a code directive to conform the tooling.
4. Fix-1's DR-19 consolidation moved a rule to a role document whose bundle did not reach two of the three roles that needed it; the reviewer caught the delivery regression; fix-2 reversed it. The reviewer then checked all sixteen consolidations for the same regression and found one more (DR-6), not raised.
5. Three executors hit the same sandbox failure (`git checkout -b <branch> origin/main` cannot write .git/config, HEAD does not move). Two self-recovered before the rule was stated, against Core 15; the third stopped per the directive's explicit working-tree rule and asked.
6. One executor refused a directive because Dave pasted it after a `/model` command and Claude Code read it as command stdout; a one-line confirmation from Dave unblocked it.
7. One executor wrote the API token to a file for curl and deleted it after. The next directive's preamble forbade it; the next executor used an environment variable.
8. MCP GitHub reads timed out twice consecutively mid-session; Dave restarted the server; reads resumed.
9. Dave: "stop suggesting that we cut corners. I will cut corners if I want to, I don't need the reminder that I can" — after CoS offered "close Pass 1 here on the evidence" as an alternative to the re-gate.
10. Dave asked for a better directive when CoS flagged its own awkward instruction 5; CoS reissued. Dave: "If you think you should write a better directive, please say so."
11. Dave reversed two reviewer-proposed dispositions on the spot and without prompting (guardrail not-overridable → Dave-only-overridable; audiences narrow → audiences broad), and reversed his own 2026-08-20 decision (prose ladder) when CoS reframed it as a different axis.
12. The directive format held for all twelve directives: one line, one paste block, executor writes the file, merges via curl, reports SHA, executes. Every SHA was verified chat-side via get_commit stats before being reported to Dave as landed.
13. Confirmation cycles re-ran sweeps over narrowing scopes; each reviewer stated when a delta was not like-for-like rather than absorbing it.

## Interpretation

- (1, 2) A dictating directive over a reconciled corpus has the same blind spot the corpus had: the decision session writes fixes file-by-file and misses the file not named. The cure was the confirmation cycle, not better dictation; five cycles was the cost of not having a bundle tool to check delivery mechanically.
- (3) A directive that edits a policy the tooling reads must name the tooling as a changed file. The decision session knew bin/ reads the metadata policy (scope.py is cited in the policy) and didn't act on it.
- (4) Consolidating a duplicate rule has a delivery check: the surviving home must reach every bundle the deleted copy reached. The reviewer did this check unasked on cycle 2; it should be in the directive that orders consolidation.
- (5, 7) Sandbox constraints that recur across executors belong in the directive preamble, stated once — and they were, after the second occurrence each. Executors follow explicit working-tree rules (evidence 5, third case) and do not reliably infer Core 15 from an unfamiliar git failure.
- (6) Paste-block delivery into Claude Code has a failure mode at the client, not the content: a preceding slash command reclassifies the paste as output. The fix is on the human side and costs one message.
- (9) Offering the cheaper path as an option is not neutral framing; Dave reads it as a nudge. State the path and go.
- (10) Dave would rather reissue than run a directive the author doubts; flagging a weakness and shipping anyway is the wrong call.
- (11) Dave's reversals were all in the direction of fewer constraints and broader delivery. The reviewer's proposals trended narrower (exempt, restrict audience, execute the old decision). CoS should present the broad option explicitly rather than default to the reviewer's.
- (12, 13) The directive format and the verify-before-report rule held under nineteen PRs with no wrong SHA reported. Reviewer honesty about incomparable deltas was consistent and useful.

## Durable insights

- **A fix directive gets a confirmation cycle; plan for three.** Convergence was 47 → 12 → 6 → 2 → 1 → 0. Budget the cycles up front rather than treating each as a surprise.
- **Name the tooling when the policy it reads changes.** Policy-to-code coupling is a changed-files question, not a separate concern.
- **Consolidation has a delivery check.** Before deleting a restatement, confirm the surviving home reaches every bundle the deleted copy reached.
- **Recurring sandbox constraints go in the directive preamble.** Branching, auth, token handling — state them every time once known.
- **Don't offer the shortcut.** State the next step; Dave will cut the corner himself if he wants it.
- **Flag a weak directive by reissuing it.** Not by shipping it with a caveat.
- **Surface the broad option.** Reviewer proposals lean restrictive; Dave leans broad.

## Candidate methodology changes

- Decision Layer, Blocks and directives: add "A directive that changes a policy the tooling reads names the tooling as a changed file and states the expected check result."
- Decision Layer or review-rubric: add the consolidation delivery check as a rule for any directive that removes a duplicated rule.
- skills/review-artifact.md: a confirmation-cycle form that admits closure tables and sweeps (already a Pass 2 item).
- Directive preamble template for this sandbox: branching (`git checkout origin/main` then `git checkout -b`), auth (curl via REST, token by environment variable), pre-existing test failures named. Belongs in a vendors/ or engagements/ file for Claude Code, not in Core.
- Decision Layer rule 4 ("Offer the next step once"): consider adding "do not offer the lighter path as an alternative unless asked."
