## Interpretation

- (1) The pre-staging rule exists and was not followed at session open; the
  baton's ordered list is the ruling and the first response should have
  carried the directive. The baton now says so in DAVE-HANDLING explicitly.
- (3, 6) Freehand directive authoring is where the session's cost went. Each
  of the three defects is mechanical — a constraint read against an
  instruction list, a literal that must not appear unfenced, a guard set
  bounded to the touched files — and each is the class `bin/check-directive`
  and the invariants document's committed regions exist to remove. The
  authoring-skill consolidation is now blocking adoption of that tooling, and
  every freehand directive until then carries this risk.
- (4, 5) "The holding session" is a route, and a route that two sessions can
  claim is a disposition violation created by the decision session, not the
  executors. Session A's three stops were the disposition rule working; session
  B's continuation was a judgment call made because the executor could see
  the amendment was authored by the issuer. The stop wording held where it was
  tested on unintended mutation; the gap is upstream, in the route line.
- (2) Four cycles for a ~300-line skill is one more than the document needed:
  cycle 2's only blocker was introduced by cycle 1's directive (6). Reviewer
  Fix text is evidence and should be carried as written unless there is a
  reason to depart; departures are where new defects entered.
- (7, 8) Reviewer sweeps and green suites are cheap confirmations that
  convert "not inspected" into evidence; the expected-state list in directives
  should be re-derived from the current suite each session rather than copied
  from the baton.
- (9) Computed cleanup over a maintained list is the decision-layer's
  state-is-computed rule applied to git; it found six times the listed
  branches and left nothing unreachable.
- (10) The connector's failure mode is silent non-delivery; "read before
  re-create" was the right rule and would have cost a duplicate PR without it.
- (11, 12) The flip-from-gate-branch pattern and the delta-amendment pattern
  are reusable as written.

## Durable insights

- A route line names exactly one session, by what it landed or as "fresh".
  Never "the holding session".
- Before sending a directive, read every constraint against every instruction
  and every self-check against every dictated string. This is the lint's job;
  until the lint is adopted, it is the author's.
- Carry a reviewer's Fix text as written; a paraphrase is where the next cycle's
  blocking finding comes from.
- Guard base verification on the files the work touches, not on directories.
- Amend by delta: new directive file citing the prior one by path @ SHA,
  worktree reused, HEAD re-pinned, first-act rule unchanged.
- Flip from a branch that contains the review artifact.
- Compute branch cleanup from the remote's merged set; force-delete locally
  only behind an ancestor check.
- After a connector timeout on a write, read state before retrying.

## Candidate methodology changes

- `skills/directive-authoring.md` (consolidation cycle, already owed): add the
  route-line rule — one named session, "fresh" or identified by a landed
  SHA — alongside the disposition rule; the disposition is meaningless when
  the route is ambiguous.
- `skills/directive-authoring.md`: state the constraint-against-instruction
  read as a pre-send check, and that a self-check in the verification block
  binds the directive's own dictated text.
- `skills/spec-review-cycle.md` or the authoring skill: a triage rule that
  reviewer Fix text is carried verbatim into the revision directive unless the
  decision record states the departure and why.
- `skills/directive-authoring.md`: base-verification guards are stated as an
  enumerated file list drawn from the directive's own scope, never a directory.
- `docs/global-context/decision-layer.md` or the Chief of Staff role: the
  baton's ordered next-step list is Dave's ruling; the successor session's
  first response dispatches item one. Dave has named this failure across
  sessions; it belongs in governed text, not in the baton.
- `bin/flip-agreed` usage and the flip-from-gate-branch precondition belong in
  the write-path usage document `specs/bin-land.md` §8 already requires, or a
  sibling.
