## Interpretation

- The stops were not caused by directive length. Every stop (5, 8, 9, 10)
  traces to the decision session asserting a fact about the tree — a tool
  name, which row holds what, a key value, a session's identity — that it had
  not read, then binding the executor to it as dictated wording. The
  executors behaved correctly each time; the cost was a full round trip per
  wrong fact. Length correlates because more specification means more
  unread facts committed to (12).
- The dictated-wording discipline, right for prose bodies the human agreed,
  is wrong for tree facts. When the executor is the one standing in the tree,
  dictating an ID or a key value to it converts its knowledge into a stop
  (5, 8). The one clean directive of the day (13) dictated only the rulings
  and let the executor derive the role list, the order and the SHA.
- Stop conditions have one setting. Four of the day's stops had a mechanical
  resolution derivable from the tree with no judgment call — highest ID plus
  one, drop the row that cannot co-render — and the executor wrote that
  resolution into its report and then waited (5, 8).
- Reviewer claims are claims (8). A finding that names rows is a tree fact
  the reviewer asserts; passing it into a directive verbatim without reading
  the rows made the reviewer's error the decision session's error.
- "Chat is never the sole record" (9) was violated under time pressure and
  cost a blocking finding and an amendment. The fix that worked was
  structural: make the directive file the record (13).
- Session identity by history is unreliable (10). One Claude Code session
  received both the execution and the review; "existing session" as a route
  gave the decision session no way to know. Routing every directive fresh
  removes the failure entirely at the cost of a re-fetch.
- Dave's tracking model (2) is the methodology's own logic — review is
  charged once per delta — and the Chief of Staff's inline-fix instinct
  worked against it. The model held for the rest of the day and the deferred
  items are all on the baton.
- Two of Dave's interventions were about framing rather than substance (11,
  18): he needs the ground floor restated when a question arrives without
  its context, and he needs an honest count when a promised "one more
  directive" becomes two. Both were met with a restatement rather than a
  defence, and both moved the work forward.
- The pre-merge bundle boundary (7) was real and mattered: the first
  rendered check (14) initially looked like a failure because the checker
  did not know the render format. The check is now known — body text, not
  IDs — and belongs in the release procedure.

## Durable insights

- The decision session's job in a directive is intent, acceptance, and
  agreed prose; tree facts are the executor's to derive and report. The
  cleanest directive of the day (13) was the one built this way.
- Make the directive file the record. When rulings are needed mid-execution,
  they go in an amendment file the executor commits first — never in a chat
  reply — and any row born of the ruling cites that file's SHA.
- Route every directive to a fresh session. Identifying a session by what it
  landed earlier does not identify what else it has done since.
- Rendered-bundle verification greps for body text; rows carry no ID
  heading in a bundle. The four-line body check used tonight is the release
  procedure's first rendered check.
- The connector's timeouts are survivable by the standing rule — read state
  before retrying a write — and were, twice.
- A reviewer's finding that names rows is a claim about the tree, read
  before it is dictated.

## Candidate methodology changes

Phrased as findings for the delta that would carry each, not as decisions.

- Rules delta (intake): a row — the decision session dictates intent,
  acceptance criteria, and any prose body the human agreed; it does not
  dictate tree facts (IDs, key values, orders, which rows hold what, tool
  names); the executor derives those from the tree and reports each
  derivation with its evidence.
- Rules delta (intake): a row — a precondition the executor can satisfy by
  reading the tree, with no judgment call and no change of intent, is
