# Retro — fiducial — 2026-09-02

## Context
A Chief of Staff decision session that opened on the queued spec-review-cycle skill cycle and ended having landed a larger change than the queue named: convergence as the standard change flow, with a new `converging` status, written across nine governed documents in one branch-scoped cycle (DEC-000360). Ten executor sessions ran; nine pull requests merged; a flush closed the session.

## Evidence
1. The cycle-11 gate's weightiest finding (N-1) asked which of three agreed texts should yield to the new Convergence section. The first proposed disposition kept all three and carved an exception for convergence. Dave refused it: the rules should say convergence is how it is done, and the contradicting texts move.
2. Dave proposed a named status rather than an in-review condition; the decision session shaped it (entry after first gate, frontmatter-only transition, edits do not reset, exit gate over a range, one ruling) and Dave added the range requirement (entry/exit SHAs, reviewer over the diff, Dave reads the diff).
3. Dave asked to set aside "the friction we've created" for the document sweep. The lever used was already in the corpus: one branch-scoped cycle over seven, then nine, documents — one Editor directive, one CQR gate over the branch, one fix, one fix-2, one confirmation-scoped re-gate, nine flips. Five executor runs instead of roughly twenty.
4. The branch gate (cycle 1) found the Editor had tangled the per-spec lifecycle with the per-change stages (N-1, criterion 12). The fix split them into two lifecycles; the fix directive pulled two role documents onto the branch mid-cycle, and the re-gate read those two full-depth while confirmation-scoped over the rest.
5. Every executor's "changed facts outside my scope" line produced work: PR #289's report named two stale sentences in a file on the branch but outside the fix's scope; a fix-2 ran before the re-gate so the re-gate read a consistent branch.
6. A Sonnet 5 executor, given a directive with no worktree-removal line, left its worktree on disk. The invariants skeleton has no Cleanup region; the obligation is author-region. Later directives carried the line; that executor cleaned up.
7. Dave's shell `$TMPDIR` differs from the executor sandbox's (`/private/tmp/claude-501`). A cleanup block written with `$TMPDIR` failed; the literal path worked. Dave's local `main` was three merges behind, so `git branch -d` refused a branch that was merged in `origin/main`; a `merge-base --is-ancestor origin/main` guard resolved it.
8. `bin/directive` general mode refuses a document argument; a script that then took `ls -t | head -1` in `docs/cycles/` picked up a committed prior flush directive and overwrote it in the decision session's sandbox clone. Restored from git before anything left the clone.
9. `bin/check-directive` M5 fired on five of the session's directives (slashless root paths in the scope list) and M2 fired on the flip directive (artifact @ reviewed-document-SHA pointer). All classified against the TRD rider queue; none worked around.
10. The re-gate directive stated the loop-start agreement bar and cadence per SR-2 before that rule was agreed — the skill under revision was applied to its own cycle.
11. Two gates and one re-gate all reported `ready-with-findings, 0 blocking`; every agreement proceeded on that verdict without a further fix round.

## Interpretation
- (1) The exception-shaped fix is the reflex when a new practice meets old rules. The corrective question is "which document is wrong?", not "how do we permit this?". It cost one turn to get there and reshaped the whole session.
- (2, 4) A status name gives tooling, readers, and executors one word for a state. Its cost showed up immediately as a lifecycle-tangling defect that a gate caught: naming the state made the per-spec/per-change confusion visible enough to find.
- (3) The friction Dave felt was serialization per document, not the gate itself. The branch-scoped cycle was already recorded practice; the win was applying it deliberately, with the re-gate's scope split (full-depth on late joiners, confirmation on the rest) written into the directive.
- (5) "Name every place outside the files you may edit" is the highest-yield line in the invariants. Both times it fired, the decision session had a fix-2 in hand before the next gate.
- (6, 7, 8) Three environment facts the corpus did not hold: no Cleanup region; executor `$TMPDIR` is not Dave's `$TMPDIR`; `bin/directive` cycle mode writes into the clone it runs in. All three are now riders or tooling-facts entries.
- (9) Two lints firing repeatedly on known-benign patterns erodes the reflex to read lint output. The riders exist; the fix should not wait for the next TRD cycle to be "reached" in queue order.
- (10, 11) Stating bar and cadence up front removed the end-of-cycle "is this enough?" conversation entirely: every flip was a one-line y/n.

## Durable insights
- When a ruled practice contradicts agreed text, the text yields; an exception is a workaround wearing a policy's clothes.
- A branch-scoped cycle is the friction lever for multi-document changes; late joiners get full-depth review in the re-gate, the rest confirmation-scoped, and the directive says which is which.
- Fix-2 before re-gate: when an executor names stale facts outside its scope, land them before the gate reads the branch.
- Command blocks for Dave name literal paths, never the executor sandbox's environment variables.
- Decision-session scripts that generate directives take the file path from the generator's own naming rule, never from directory listing order.
