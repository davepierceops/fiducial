# Retro — fiducial — 2026-08-24

## Context

Dave opened with "I don't know where we are": two batons from different
sessions (one turned out lost), a directive he believed never ran, and a Claude
Code report he didn't know where to paste. The session computed state from the
repo, reconciled everything, merged two branches (DEC-000190; bin/land plus its
red-gated test), inventoried the bundle system, hand-built four writing bundles
for cross-vendor use, and captured a draft PRD for a row-granular bundle
system. It also spun off the Illuminait engagement into its own baton.

## Evidence

1. Every "where are we" question was answerable from the repo alone: branch
   heads, directive-recording commits, and the absence of work commits told
   the story before any baton was read. The lost baton turned out not to
   matter.
2. I asserted the reset-test session was "alive and mid-task" from a
   transcript that said "continuing." It had been 20 hours and 100 miles.
   Dave caught it; the repo showed no work commit. The session *was* still
   alive, but my claim was unlabelled inference presented as fact.
3. The baton-of-record said `git worktree add` no longer works. The
   bundle-spine executor's report said it works with `--no-track`. The two
   sources disagreed; the repo could not adjudicate; the executor's was an
   observed claim and the baton's was carried-forward inference.
4. The bundle-spine executor's worktree showed 137 baseline test failures;
   both clone-based sessions showed 2. Nobody noticed until the counts were
   placed side by side in this session.
5. I sent a command block that put a tarball on `~/Desktop`. The corpus
   already had a location convention (DEC-000190 writes to `~/code/`), which
   I had not read. Dave: "every fucking agent makes some bespoke decision
   about where to store shit." He then rejected `~/code/` too and chose
   `~/Downloads`.
6. Dave, on the same point: "we just have way too much context. There's too
   many lines. No wonder you don't follow them. You get a thousand of them."
7. `bin/bundle --list` × 17 audiences, run in a sandbox clone, produced in
   one command the inventory that no baton had. It showed: the all-roles floor
   carries three specs; the hand spine (12 files) and the tool (35 files)
   disagree; `engagements/sre/` exists, is agreed, and appears in no bundle
   any recent session received.
8. The GitHub connector 404s on `davepierceops/writing` though a push to it
   succeeded seconds earlier. Read access to a private repo is an app
   permission, not a repo property.
9. The four writing bundles were built by hand in minutes, from role docs
   that each say "governed by `prose-criteria.md`, read it first." The
   file-set rule was in the role text, not in tooling.
10. Dave asked for a draft PRD "so nothing lives in chat" while explicitly
    refusing a PRD cycle. The draft went to disk, uncommitted.
11. Dave asked for the Illuminait conversation now, while waiting on an
    executor, "because I'm a human, so I'm always thinking about time."
    Two topics were interleaved in one session without loss because each
    landed in its own artifact (a baton; a merge; a PRD draft).

## Interpretation

- (1, 7) State computed from the repo beat state carried in batons every
  time. The baton's value was the *decisions and findings* that live nowhere
  else, not the state. Batons should shrink toward that.
- (2, 3) Two claims went out unlabelled and one was wrong. Core rule 6 is in
  the loaded bundle; I still did it. Loading a rule is not following it —
  which is (6).
- (4) Three executors ran the same suite in three environments and got two
  different answers, and none of them was asked to compare. Environment is a
  verification boundary nobody declared.
- (5, 6) The failure was not "no convention" but "convention not read, then
  a bad one chosen anyway." Both halves point the same way: fewer rules,
  each one actually load-bearing.
- (7) Inventory-by-tool is cheap and decisive; the sandbox clone of a public
  repo cost one command. Inventory-by-baton was silently incomplete for a
  week (`engagements/sre/` unknown to every recent session).
- (9) A corpus whose roles state their own inputs in prose is already a
  bundle spec; tooling is a convenience over it, not a prerequisite.
- (11) Interleaving two topics was fine *because* each produced a durable
  artifact promptly. The risk is topics that produce none.

## Durable insights

- Compute state from the repo before reading any baton; then read the baton
  only for what the repo cannot hold.
- A public repo can be cloned into the chat sandbox and its tools run
  directly. Use this for any inventory question instead of reasoning from
  file listings.
- Every test count reported by an executor is environment-specific until
  proven otherwise; ask for the environment (clone vs worktree) alongside
  the count.
- When a rule is followed by nobody, the fix is subtraction, not emphasis.

## Candidate methodology changes

- **Decision Layer / baton rule (13):** a baton carries decisions, findings,
  and pointers — never computed state. State is re-read from the repo.
- **Core rule 6 or the executor report shape:** test counts carry the
  environment they were observed in (clone, worktree, sandbox), stated as a
  boundary.
- **A location convention for files handed to Dave:** `~/Downloads`, named
  to sort to the top. One line, in the Decision Layer, replacing any per-tool
  convention (DEC-000190's `~/code/` for bundles).
- **Review rubric, criterion 10, applied per rule not per file** — captured
  in the bundle-system draft PRD; the audit is the next work.
- **Sandbox companion docs:** `git worktree add … --no-track`; keychain
  noise on clone and ls-remote as well as fetch/push.
- **Writing corpus:** `prose-criteria.md` audience gains `reviewer` and
  `skeptic`.
