## Durable insights

- A decision session that spawns its own reviewers must set the reviewer's
  model, not inherit it: the inherited default is the most expensive one, and
  nothing in the harness warns. One frontier read per package is right for
  code (3a's found three silent-failure defects); for prose and mechanical
  moves the solid tier found everything the frontier tier would have.
- The review-then-amend-then-re-read loop costs a full reviewer run per
  re-read. Under DEC-001000 a package with only non-blocking findings needs no
  re-read, and a blocking finding that is a one-line fix can be verified by
  the decision session itself (6a). The re-read is for a design error.
- Execution blocks to a different vendor's agent work when the repo carries
  the context: Codex read SPEC.md, the plan, the log and the sort table and
  produced conformant artifacts. The block's job is to name the sections and
  the acceptance, not to restate them.
- Appending decision entries on the next package's branch races the previous
  merge; the log needs either a dedicated landing per merge or allocation by
  highest id rather than last entry.
- Harness facts to plan for, now observed twice: `isolation: worktree` denied
  in this harness; agents waiting on an approval prompt die on a server
  restart and resume from transcript; the five-hour cap kills mid-run and
  the resume works.
- The task-list widget is the running indicator the human wants; it costs
  nothing and its absence reads as silence.
