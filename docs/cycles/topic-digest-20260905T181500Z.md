~~~markdown
### <n>. <source path> — <rows> rows → <distinct> distinct → <surviving> after retirement

**Divergent.** <for each divergent cluster this topic sits in: the C-id, one

**Retiring.** <count> rows: <one clause naming what they governed; "none" if
none>.

**Proposal.** One of: keep as topic `<name>` / merge into `<other topic>` /
rename to `<name>` / split into `<a>` and `<b>` — one line, with the reason in
a second sentence. The topic name is a lowercase word or hyphenated words taken
from the file's basename unless the proposal renames it.
~~~

The retirement criterion. A row retires when its obligation exists only to
operate the document-lifecycle machinery retired by DEC-000380 (decisions/log.md
at the base ref): the `status` and `last-reviewed` frontmatter fields, the
agreement flip, per-document review cycles and their artifacts, the expedited
and doc-only paths, the frontmatter in-scope set, the pre-commit hook, and the
tools check-frontmatter, flip-agreed, install-hooks, migrate-frontmatter, and
reviews/expedited-log.md. A row that states an obligation which survives the
machinery — that a document is reviewed by a frontier read before Dave signs it
off, that a decision is recorded in the log — does not retire even if its
source sentence mentions the machinery; count it as surviving and, where its
wording is bound to the machinery, name it in the header's borderline list.
When unsure, the row survives; the digest never retires a rule Dave has not
ruled on.

Counting rules. "Distinct" for a topic counts each cluster the topic
participates in once plus its singletons, so a rule shared across files is
counted in every topic that states it and the header notes that topic
distinct-counts therefore sum to more than 1131. "Surviving" is distinct minus
the retiring distinct rules. Every count is reproducible from the companions;
state in the header the one-line method for each.
