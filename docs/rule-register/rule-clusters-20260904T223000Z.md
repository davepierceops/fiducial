Method notes, stated so the count is auditable.

1. **Session kinds.** A `binds` of `all` covers every party; a session-kind bind (`decision`, `execution`) covers the roles that run as that kind — so `decision` covers `chief-of-staff`.

2. **Parallel role statements.** Where two rows state the same obligation and differ only in that each binds the role its own file is about, the pair is `same`: each agent reads its own file and behaves identically, so no agent could act differently. `same-with-divergence` on party is reserved for pairs where the coverage genuinely differs.

3. **Enactor and checker.** A row that requires a thing be done and a row that requires it be checked are clustered together and marked agreeing — the rubric criterion and the rule it tests are one rule, stated from two sides.

4. **Enumerations.** Rows enumerating the triggers of one obligation, or the members of one prohibition, are clustered as `same` where the obligation itself is identical across the members and the corpus names the list as a class — the boundary-declaration triggers, the consequential-class members, the false-confidence claims, the listed prose tells. Where a member states its own distinct obligation and has a counterpart elsewhere in the corpus, it is its own rule: the spec-reviewer checklist, the review-artifact field placements, and the PRD/TRD non-functional dimensions are not collapsed.

5. **Definitions.** A definition clusters only with another definition of the same term. Role session-kind definitions ("the Coder runs in an execution session") name distinct terms and do not cluster with each other; the self-referential audience declarations do, because every instance says the same thing about the document in hand.

6. **Compound rows.** A few rows state two rules at once (R0018, R1486, R1483) and so bridge clusters that transitive closure then merges. Every row is in exactly one cluster, so the bridge is kept where the row genuinely restates both, and cut where it does not — see the verification note below.
