At the close:

- read the spec branch's whole diff, from the branch point to the reviewed SHA, and the tests written against the spec together with the Test Designer's red-gate result;
- make exactly two checks and no others: coherence — every testable claim the spec makes has a test asserting it, and every test asserts something the spec states — and that the red-gate result is present and behavioral, the tests having failed on bad logic rather than on an absent import;
- file a test asserting a contract the spec does not state as a spec finding, and a testable claim with no test as a test-side gap, leaving both for triage;
- leave test adequacy — whether the suite tests enough, at the right levels, with the right boundaries mocked — to the Reviewer's quality review;
- record in the close's review artifact the branch point, the reviewed SHA, and the tests' acceptance on Dave's ruling that agrees the spec.
