The consequential class is exhaustive. A change is in it if it touches authentication or authorization; a schema or data migration; security or privacy controls; an irreversible or hard-to-reverse operation such as data deletion or a destructive migration; the first exposure of a new surface or feature to users, such as a flag flip, a rollout, or a new endpoint going live; a breaking change to a public interface, such as an API contract change, a removed endpoint, a changed response shape, or a renamed or removed UI flow; pricing, billing, or entitlements; user data visibility or sharing; a verification boundary, meaning adding or removing a live integration, changing a fixture for external data, or moving a boundary's verification class; core architecture, meaning the standing TRD; a code path for a Top K user journey whose SLO error budget is at or below 20% remaining; or a per-change architecture summary that moves a boundary. A change touching none of them is routine and flows to release on evidence, with no explicit human go/no-go.
